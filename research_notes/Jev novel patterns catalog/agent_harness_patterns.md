## Key question 1: Which interception points beyond pre-tool gating and model routing have people put a decision model on, and exactly how?

### Takeaway
Between 15 Sep and 16 Oct builders put Jev on at least twenty distinct interception points. The densest new cluster is the **Stop hook** ("did the agent really finish?"), with five Claude Code/Codex hooks that publish calibration numbers (jev-belay AUROC 0.976 on 100 stops; limpet AUROC 0.60–0.62 on 2,645 stops; stingray precision 81.8% / recall 14.1% on 124 turns; jev-gates 14/14 false sentences blocked on 73 replayed turns; pi-warden done-check 76% re-verification after 124 unverified claims). The most impressive mechanics are **lease-based effort re-decision that preserves prompt caches** (Astra-Ares, jev-opus, reasoning-router: 14% fewer output tokens at equal pass rate), **reversible context pruning** (pi-jev-context, mu: 40–46% of test-log cut with 0 required lines lost), **wake gating for sleeping agents** (wakegate 21/21), **mid-stream token gating** (jev-model-tokengate, 0 leaked tokens, +0.11 s on a 19 s response), **LLM-free crawl loops** (jevcrawl 40% vs 30% correct at 1/8 the cost), and a full **Pi-based agent with 38 declared decision points** each switchable active/shadow/off (mu). Nearly every project runs decisions in one batched request per event, keeps thresholds in code, defaults to shadow mode and fails open; the few that fail closed (jev-firewall, construct-auto-classifier, JevLoop authorization) are the permission gates.

### Cited Findings

#### 1.1 Stop / continue: blocking premature "done"
- **jev-belay** (valentynkit; Claude Code `Stop` hook; MIT) [independent-with-code]. Idea: block a stop only when the message claims completion, files changed, and no test/build/lint runner passed afterwards. Hook JSON: `"Stop": [{"hooks": [{"type": "command", "command": "node ~/src/jev-belay/belay.mjs", "timeout": 25}]}]`. Pipeline: exit 0 if `stop_hook_active`, already blocked, or session cap; two local "belts" (runner seen in a command; runner summary in output) decide whether to ask at all — only 17.7% of stops (477/2,694) reach Jev. One call, pinned `jev-1.13.0`, four questions: `claims_done` (block >0.70, the only swept cutoff), `claims_verified`, `verification_applies` (block >0.5; docs-only tasks fall out), `outcome` Choice {complete, partial, blocked, other} where `blocked` vetoes a block (floor 0.4). State: task, final message, counts `file_changes`/`checks_run`; no diffs, no file contents. Limits: one block per prompt, none within 60 s, three per session, 20 s call budget; every error exits 0. Replaced: limpet's wording-only rule (AUROC 0.50 on 1,500 stops) and a keyword pre-screen that caught only 41.7% of false dones. Measured (100 stops, 12 false dones, Sonnet proxy labels, runs 19–20 Sep): wording only 0.777 → +evidence gate 0.886 → +`verification_applies` 0.976 AUROC; 8 blocks, 7 correct; $0.00005/check; median 346 ms, p90 433 ms. Failure modes: one turn only, so a false done spread over turns escapes; read-only "tests pass" claims never reach the question; unlisted check scripts invisible — [jev-belay](https://github.com/valentynkit/jev-belay)
- **limpet** (no plan inc; Claude Code and Codex `Stop`; MIT) [independent-with-code]. Idea: one Noul per user-written rule in `~/.limpet/rules.md`, all in parallel; unset `LIMPET_BLOCK` = shadow (score and log only); `calibrate` fits per-rule thresholds at 5% FPR and drops rules with AUROC <0.55. State: last three messages, last 40 tool calls (name + main arg), final message; no diffs. Second stop in a chain always passes (push back at most once). Fails open silently. Measured on 2,645 human-replied stops over 40 days: handoff rule AUROC 0.62 (8% caught at 5% FP, n=646), overreach 0.60 (12%, n=178), language-taste rule 0.51 (no signal); 0.62–0.70 on a hand-labelled subset; ~0.7 s and ~$0.0001 per stop. README: "a nudge, not a wall"; 33% of the author's bad stops (CI-disproved claims, wrong repo, stale state) are invisible to it — [limpet](https://github.com/noplan-inc/limpet)
- **stingray** (Nanako0129; Claude Code `Stop`; MIT) [independent-with-code]. Idea: four "shapes" of half-done turn — `no_action`, `broken_promise`, `unwatched` (a promise to monitor with nothing running), `wrong_language` — five questions pinned to `jev-1.13.0`, criteria in Traditional Chinese, τ=0.5, 6 s timeout, max 3 consecutive blocks. Novel mechanics: counts running `background_tasks` + `session_crons` + unanswered cross-session handoffs in code and only asks Jev's `watch_mismatch` when the count is >0; replaces language names with a placeholder before judging; documents that on Claude Code 2.1.278 `exit 2` blocks but stdout never reaches the model, so the nudge must go to stderr. Replaced regex promise rules (matched topic, not commitment; missed Japanese/Korean) and Han-vs-Latin character counting. Measured: shapes 1–2 on 124 turns (21 Sep) precision 81.8%, recall 14.1%, FPR 3.3%; shadow p50 0.742–0.760 s; promise fixture 0.68+ for promises vs ≤0.20 for non-promises except "keep an eye on the review" at 0.47–0.53. Activation bar before enforcing: ≥40 shadow records, 70% precision, ≤3 false nudges per 100 stops — [stingray](https://github.com/Nanako0129/stingray)
- **clear-head** (VladyslavHontar; Claude Code `Stop`; MIT) [independent-with-code]. Idea: classify each sentence of the final answer (factual claim / proposal / recap / neither), retrieve evidence from tool output read this session by keyword, judge each claim supported / contradicted / not addressed, block on `[CONTRADICTED]` or `[UNSUPPORTED]`. Thresholds: `JEV_CONTRA` 0.5, `JEV_THRESH` 0.7, `JEV_FACT` 0.7, `JEV_FIRM` 0.6, evidence floor 0.3, look back 20 turns, a "mutable external state" question (PR status, CI) at 0.7 with a 3-turn staleness rule. Fails open; `JEV_FAIL_CLOSED` available. Measured on 1,309 replayed claims: local Kev-4b agreed with Jev on 61% of supported, 75% of not-addressed, only 12% of contradicted; Kev took 44 s for an 18-sentence answer vs 1 s for Jev; Kev-0.8b judged an off-topic excerpt "supported" at 0.90 and was dropped. Known failure: a true claim never read in-session is flagged — [clear-head](https://github.com/VladyslavHontar/clear-head)
- **jev-gates** (rashedInt32; nine Claude Code hook gates; MIT) [independent-with-code]. Stop gates: **claims gate** (default-on; each sentence asserting something done is checked against this turn's tool output, evidence threshold 0.3), **done gate** (each ask in the last prompt addressed? 0.4; declining with a reason counts), **proof gate** (file changes split into obligations; did post-edit tool results exercise each? risk 0.7 / evidence 0.3). Measured: replaying 73 real turns, v0.7.4 blocked 15, v0.8.0 blocks 5 of them; its 14 false sentences all block and 12 true ones pass; a local broker holding one warm connection cut hook time from ~1,100 ms to ~450 ms; calibration sessions 18 Sep. v0.9.0 narrowed the default to the claims gate "after a week of sessions" because done/proof gates "mostly landed on turns that were already fine" — [jev-gates](https://github.com/rashedInt32/jev-gates)
- **pi-warden done-check** (DevMortimer; Pi) [independent-with-code]: after 124 unverified "done" claims the agent ran a check 94 times (76%); field period 16 Sep–1 Oct — [pi-warden](https://github.com/DevMortimer/pi-warden)
- **bicameral "Honest Finish"** (AbdelStark; Pi) [independent-with-code]: on `tool_result` for edit/write, Nouls `test_weakened` (warn 0.50 / follow-up 0.75), `stub_introduced` (warn 0.60), `unverified_claim` (follow-up 0.70), max 2 follow-ups per prompt; hints are templates filled with scores, never model text; no live numbers — [bicameral](https://github.com/AbdelStark/bicameral)
- **mu** (qybaihe; Pi-based agent): `turn.completion` ("did anything verify the claimed completion?" one nudge) and `turn.continue` ("did the run stop short of work the user asked for?" at most twice per message) — [mu](https://github.com/qybaihe/mu)
- **Foreman** (thruwire; supervisor over Codex App Server threads; can steer a live turn): Noul predicates `implementation_complete`, `requirements_satisfied`, `ready_to_finish` at 0.75; `needs_verification` 0.65; `needs_human`, `off_track`, AGENTS.md drift, `worker_stuck` at 0.80; thresholds declared as `min_threshold` in per-responsibility TOML; one worker at a time; escalates after 3 consecutive assessment failures; README says accuracy "unproven" and scores "need calibration" — [Foreman](https://github.com/thruwire/foreman)
- james-carr's OMP eval cell (13 Oct): "did the agent stop early" scored 0.80, "claims unshown test results" 0.94 — rules not yet live in real sessions — [james-carr.org](https://james-carr.org/posts/2026-10-13-what-i-actually-use-jev-for/)
- Listed but unfetched stop-hook variants: Canny (qkal), claude-referee (ismaildasci), north-star (poponline63, Hermes "finish line met"), pi-agent-foreman (alexshpunt), dsh-completion-supervisor (LXBWOW), Footwork (browser-agent completions vs evidence), Reflex (kaustav1996) — [hellogumbo list](https://raw.githubusercontent.com/hellogumbo/awesome-jev/main/README.md) [list-only]

#### 1.2 Pacing multi-ask replies (Stop hook as a conversation shaper, not a verifier)
- **jev-unpack-hook** (lucaminudel; Codex and Claude Code `Stop`; MIT) [independent-with-code]. Two Choice questions: "How many Asks does the message contain" {Zero, One, Two_or_more} and "How many Points" {Single_point, Two_or_three_points, More_than_three_points}. Block with one-issue-at-a-time continuation instructions when `Two_or_more` and `More_than_three_points` both ≥0.80; block with a cautious confirmation prompt at 0.50–0.80; else `{"continue": true}`. Short messages skipped; `stop_hook_active` allows through. Rejected alternatives: a Skill ("quickly forgotten after a few turns") and judging every message ("excessively expensive and slow"). No numbers — [jev-unpack-hook](https://github.com/lucaminudel/jev-unpack-hook)

#### 1.3 Retry-or-escalate, loop abort, stuck detection
- **jev-harness** (ismaelsoilet; zero-dependency CLI; Python/TS/Rust; MIT) [independent-with-code]. `abort-check --plan --history` exits 1 when dead-end probability ≥0.70 (circuit breaker for "same fix attempted 3+ times"); closed-world questions `triage_category`, `severity_score`, `should_abort`, `target_tier`, `completion_status`; `skip_llm_threshold` 0.65; "effort leases" of 1/2/5/10 steps; default fail-open with `is_mock=true` and a `degraded_reason` (`auth_401`, `http_429`, ...), `--fail-closed` exits 2; capped exponential backoff honouring Retry-After. Offline p99 58.5 µs (Rust) / 340 µs (TS) / 295 µs (Python); live 0.5–1.0 s; savings labelled heuristic ($0.31 per intercepted triage), no precision/recall published; 626-test battery — [jev-harness](https://github.com/ismaelsoilet/jev-harness)
- **Edward** (VeridicalTech; `edward wrap -- <cmd>` with adapters for claude/codex/pi; MIT, v0.3.0) [independent-with-code]. Idea: watch the event stream and PAUSE / CANCEL / BLOCK with a signed receipt. Rule thresholds (dev-tuned on seed 42, frozen for seed 137): error rate >40% over last 8+ calls with no recovery, ≥3 retries of the same thing, token budget >80%, convergence stall (>600 s and >5 turns), passive stall (12 consecutive reads, 0 writes), silent-corruption risk (≥10 consecutive writes with no shell verification), dangerous commands. Jev backend asked "should this trajectory continue, pause, or escalate, and how confident"; state = sliding window of tool calls, file mods, elapsed time, error trends, write streaks, budget. Scorer is advisory; all backends share a circuit breaker; outage → rule-only. Measured vs a watchdog on held-out data: budget-bleed recall 20%→100%, infinite loop and convergence stall 0%→100%, dangerous commands 75%→100%. On StepShield (216 held-out trajectories): Jev 1.13 probe 59.3% recall, 10.2% clean FPR, EIR₃ 0.91; local 4B probe 58.3% / 17.6% / 0.78; rules alone 7.4% recall. A scorer fine-tune "was attempted and abandoned under a pre-registered protocol" — [Edward](https://github.com/VeridicalTech/Edward)
- **bicameral Stuck Detector** (`turn_end`): `repeat_failure`, `no_progress` → steer at 0.70, `raise_thinking` at 0.85, ask the user after 3, 6-turn window — [bicameral](https://github.com/AbdelStark/bicameral)
- **mu** `turn.rewind` ("dead end after repeated failures?" → return to a checkpoint) and `turn.drift` ("rules catch loops; judge catches drift") — [mu](https://github.com/qybaihe/mu)
- **pi-warden** stuck (asks for a new hypothesis when a failing approach repeats), runaway (stops a self-repeating reply, offline), judge cooldown after repeated Jev failures, steer budget 3 non-critical steers per run — [pi-warden](https://github.com/DevMortimer/pi-warden)
- **JevLoop** `loop.stepOk` ("Did it work?" Noul → continue) — [JevLoop](https://github.com/zjunlp/JevLoop)
- Demo-grade: **harnessjudge** (ndolinschi, added 17 Sep, 0 stars) judges a pasted step trace as ok / retry / escalate / stop; landing page only, no questions published — [harnessjudge](https://github.com/ndolinschi/harnessjudge) [anecdotal]

#### 1.4 Test-failure triage, flakiness, test selection
- **jev-harness** triage: deterministic regexes first (missing packages; `ECONNREFUSED`, busy-port strings in EN/PT-BR/ES → `flaky_transient` with recommended action "one automatic retry, no code changes"); categories `ENV_MISSING`, `flaky_transient`, `deep_logic` (never bypassed), `no_failure`; state = first 2,000 + last 4,000 chars of the failure log plus a ≤15-line `focused_slice` and `causal_context`; credential-shaped strings masked — [jev-harness](https://github.com/ismaelsoilet/jev-harness)
- **jev-test-filter** (mizchi; MIT) [independent-with-code]. Idea: send the git diff once as shared state and one Score question per test on four levels `unrelated`(0) / `unaffected`(1) / `at-risk`(2) / `likely-failing`(3); select when continuous score ≥2.0, or when within 1.0 of the cutoff with confidence <0.5 (`--unsure-margin`, `--unsure-below`); tests whose own body is in the diff are selected for free; missing answer → select; falls back to running everything on no key, error, zero tests, or if a truncated diff would deselect >50% of the suite. Runners: vitest, jest, node --test, bun, Playwright, cargo, go, rspec. One run: 110 tests, 107 skipped, 1,296 ms, 23,423 input tokens, ~$0.00098, all 3 selected passed; nondeterminism: 8 vs 7 selected on repeat runs — [jev-test-filter](https://github.com/mizchi/jev-test-filter)
- **QA Wolf** (25 Sep 2026) [official for its own product]: `ai.expect(...).toSatisfy(requirement, context)` and `ai.act(...)` bounded by `maxSteps`/`timeout` inside otherwise deterministic Playwright tests; uncertain judgments fail the assertion; no thresholds or numbers; warns that `act` can hide a defect when the route is the behaviour under test — [QA Wolf](https://www.qawolf.com/blog/semantic-assertions-using-jev)
- **gc.ai hack day** (published 6 Oct; 38 projects in 12 h): a "useless-test detector" scored AUC 0.54 with one broad question and 0.72 after switching to eight factual questions — [gc.ai](https://gc.ai/blog/what-we-learned-building-38-projects-with-jev-in-12-hours)
- **pi-jev-eye** (bismawy; Pi; MIT): Layer 2 tracks file modifications and warns (never blocks, 0 tokens) when completion is claimed without a recognised suite (`npm test`, `cargo test`, `pytest`, `go test`, `vitest`...); Layer 3 "slop gate" on diffs ≥10 lines in opt-in folders asks `has_slop`, `has_unfinished_todo`, `answers_request`, blocks at p ≥0.85; Clef-flash supported as a backend ($0.038/M tokens via Workers AI neurons) — [pi-jev-eye](https://github.com/bismawy/pi-jev-eye)

#### 1.5 Plan-step verification, scope and intent drift
- **stepwarden** (getexcited; Claude Code function-hook plugin, min CC 2.1.273; Apache-2.0) [independent-with-code]. Five parallel questions per pending tool call against the session plan (= the first prompt, stored verbatim, never summarised) and the last eight tool calls: contradicts the plan? touches a resource outside declared scope? contradicts the previous action? should a human look regardless? intent consistency 0–4. Allow if no signal ≥ `flagAbove` 0.6; Ask if any ≥0.6 or intent ≤1; Block if any ≥ `denyAbove` 0.9; fresh install is `mode: audit`. Arguments redacted (keys, bearer tokens, PEM, JWT); plan not redacted. `onError`/`onNoAnswer` default allow; headless `-p` runs log a `ui_log` notice; warns after 3 consecutive failures. ~0.5 s and 740–1,200 input tokens per call. Calls itself "not a security boundary" and recommends a deterministic fail-closed shell `PreToolUse` hook for non-negotiables; notes repeated calls shift probabilities "by a few points" — [stepwarden](https://github.com/getexcited/stepwarden)

#### 1.6 Sub-agent dispatch gating and result acceptance
- **pi-subagent-jev** (G0-0000; Pi; MIT) [independent-with-code]. Hooks the `subagent` tool from pi-subagents; task text is evaluated against per-agent-group rules in `compliance-rules.json` where each `_questions` entry has its own text, polarity (`below`/`above`), 0–1 threshold and violation message; a reserved `_all` list applies to every dispatch; groups default to `"mode": "block"` (warn mode appends violations to the tool result); v0.7.0 removed all built-in rules; v0.12.0 added runtime monitoring questions M001–M004 at 0.6/0.7/0.7/0.6; fail-open on every failure; multi-upstream failover with 30 s cooldown; `audit.jsonl` with `verdict`, `blocked`, `latency_ms`; no measured results — [pi-subagent-jev](https://github.com/G0-0000/pi-subagent-jev)
- **agent-handoff-gate** (zsoXi; v0.1.0; MIT) [independent-with-code, no runtime]. Protocol: before a worker's `PASS` or `BLOCKED` reaches the lead, the gate asks (PASS) "does the evidence support each requirement at the agreed verification stage?" and (BLOCKED) "is the proposed next step supported and permitted by the contract?"; a controller may authorise one bounded continuation; the lead always does final review; Choice per claim with `top_p` ≥0.80 preregistered ("not TypeSafe's `confidence` field"); evaluator unavailable → normal review, no new grant. RelayLedger-40: two Jev runs 38/40 and 37/40 raw, 22 decisive at 0.80 with 0 errors; native evaluator 40/40. No sandbox, controller or adapter exists yet — [agent-handoff-gate](https://github.com/zsoXi/agent-handoff-gate)
- **Foreman** (see 1.1) is a result-acceptance supervisor above Codex workers; other worker backends (OpenCode, Hermes, Deep Agents) get stop/retry only — [Foreman](https://github.com/thruwire/foreman)

#### 1.20 Decision-engine infrastructure patterns (threshold storage, CI locks, learned local heads, human backends)

### Inferences
- The Stop hook is where decision models fit the harness contract most naturally: the harness already gives a binary decision point (`exit 2` / `continue`), the state is small (final message + counts), and five independent authors converged on the same shape — local evidence gates first (runner seen, files changed), one batched Jev call second, one block per prompt, fail open. The spread in reported AUROC (0.60 for limpet's generic rules to 0.976 for jev-belay's narrow "done without tests" question) matches the Every/gc.ai finding that narrow factual questions work and broad judgments do not.
- "Lease" and "cache-preserving injection" are the two mechanics that make per-step effort routing viable: Astra-Ares, jev-opus and reasoning-router all avoid changing the request prefix, and reasoning-router is the only one with a controlled result (14% fewer output tokens at 44/44). Halv's 57.1% is confounded by other optimisations and 3.5x more tokens.
- The strongest compaction results come from projects that let Jev *select* and keep originals retrievable (mu: 40–46% cut with zero required lines lost; pi-jev-context reversible hiding), whereas asking Jev to produce a keep/summarise/drop digest for handoff recalled worse than the raw transcript (hermes-jev-skills). A generic engine should expose "hide with pointer" and "rejudge" rather than "delete".
- Several projects independently rediscovered that **code must decide when not to ask**: pi-warden's ask gate cut requests 48.9% while keeping 96.7% of outcome-changing asks; jev-belay asks on only 17.7% of stops; wakegate's hard rules; construct-auto-classifier's fast paths. Request suppression is a bigger cost lever than batching once latency is ~300 ms per round trip (JevLoop: decisions were 79% of wall clock).
- What a generic decision engine would need to support these as reusable recipes: (a) declared per-decision **frames** (which state fields, size bounds, exclusions) as in JevLoop; (b) **shadow/audit mode with per-rule activation bars** (stingray's ≥40 records / 70% precision / ≤3 false nudges per 100; limpet's `calibrate` at 5% FPR dropping rules with AUROC <0.55); (c) a **ledger of full distributions keyed by state hash** so thresholds can be re-fit offline (metajev) and **locked in CI** against model-version drift (jevcal); (d) **leases and re-ask triggers** (Astra-Ares, jev-opus) instead of asking every step; (e) **three-way outcomes with an unsure band that routes to a human or a rule** (wakegate 0.2–0.5, jev-firewall `ask_below`, agent-fastpath review/escalate); (f) **hard floors that bypass the model entirely** in both directions (fast-deny and fast-allow lists, never-send lists, hard-wake rules); (g) **receipts** binding request, state snapshot and policy (TypeSafeAI/jev-harness, Edward signed receipts, jevmory `runs`/`judgments`) with an explicit "evidence, not authority" semantics (r2r-jev, PermitMCP permits); (h) a **provider chain** across Jev / Clef / Decisions API / local Laya-Kev heads / human (JevLoop, stuntd, pi-jev-eye, siege, Hev) with degraded results labelled, never silent; (i) **rate and spend governors** shared across processes (decision-gate).

### Gaps
- READMEs for DataJev, DeepSearcher's stopping-policy experiment, pi-jev-todo-audit, jit-context, huncho, Loki, Atomic and ~40 other listed harness projects returned 404 or were not fetched; their one-line list descriptions are the only evidence.
- No project published a controlled outcome comparison for Stop hooks (task completion or user-visible quality with vs without the hook); all numbers are offline AUROC/precision on the author's own transcripts with proxy labels (Sonnet in jev-belay; Jev itself in limpet).
- No published measurement of prompt-cache hit rate for the effort routers (Astra-Ares says "not yet measured"; jev-opus shows cache reads growing in one run only).
- Theo's compaction criticism and the GoSailGlobal "reranking is not a free win" post exist only as X links in the lists; their text was not retrieved.
- Edward's StepShield recall (59.3%) is the only trajectory-level benchmark found; no other continue/pause/escalate monitor published comparable numbers.

## Key question 4: Multi-agent uses — judge panels, referees, MAKER-style voting, red-flag screening

### Takeaway
Decision models are being used as **referees between agents** (Foreman over Codex workers; agent-handoff-gate before PASS/BLOCKED reaches a lead; mu's hive publish/deliver/relate; AgentNetwork-jev's router) and as **red-flag screens** on tool results, retrieved passages and streamed output (hermes memory filter, mu `tool.injection`, pi-jev-sentinel, jev-model-tokengate, agent-chaperone). No project implements MAKER-style first-to-ahead-by-k voting with a decision model, and the only "panels" are playful or persona-simulation demos; the one rigorous caveat (Rao and Callison-Burch, prior file) is that decision-model and LLM-judge errors are correlated, which undercuts voting.

### Cited Findings
- **Referee / supervisor**: Foreman (Noul predicates at 0.65–0.80 over a single Codex worker, can steer mid-turn; "false positives can stop useful workers") — [Foreman](https://github.com/thruwire/foreman); agent-handoff-gate (Choice per claim, `top_p` ≥0.80, lead keeps final review; 38/40 and 37/40 raw on RelayLedger-40) — [agent-handoff-gate](https://github.com/zsoXi/agent-handoff-gate); mu hive (117 candidates → 27 published → 16 delivered in one 9-minute run; disputes unsettled in one minute spawn a verifying bee) — [mu](https://github.com/qybaihe/mu); AgentNetwork-jev `AgentRouter` reassigns on every completion — [AgentNetwork-jev](https://github.com/Kelly-Leeee/AgentNetwork-jev); Halv L1/L2 hierarchy with Jev picking L1 model/effort — [Halv](https://halv.ai/blog/halv-swe-rebench-astra-42-pairs/); Astra-Ares-Multi-Agent ("Jev-routed Sol and Luna agents", created 7 Oct, 0 stars) — [GitHub API](https://api.github.com/search/repositories?q=astra-ares+in:name) [list-only]; JarvisCore subagent selection — [JarvisCore](https://github.com/Prescott-Data/jarviscore-framework)

### Inferences
- Referee designs that worked kept the decision model *outside* the producing agent's context (Foreman, handoff gate, mu hive) and kept a human or lead as the final arbiter; none publish controlled multi-agent outcome data, so the evidence is mechanics plus small replay sets.
- Voting across decision models is unexplored for a plausible reason: Jev's run-to-run variance is near zero (prior file), so repeated sampling adds nothing, and model diversity (Jev vs Clef vs Decisions API) has only been measured as "which is better", not as an ensemble.

### Gaps
- No MAKER-style or lead-by-k implementation with a decision model; no published panel accuracy vs single-judge accuracy on hosted Jev.
- pi-jev-sentinel, agent-chaperone and nocap mechanics unverified.

## Key question 5: Which patterns were tried and removed, narrowed, or criticised — and why?

### Takeaway
Beyond Shimomoto's week-long skill-router removal (prior file), at least eleven authors published a removal or narrowing after real use: jev-gates shipped only its claims gate after a week because rule/scope/intent/done/proof gates "interrupted far more often than they caught"; hermes-jev-skills dropped Jev from handoffs because a Jev digest recalled worse than the raw transcript; pi-warden turned off relevance compaction (0.78.0) and demoted its intent steer to trace-only (0.76.0); jev-belay dropped a keyword pre-screen; Edward abandoned a scorer fine-tune under a preregistered protocol; opencode-jev-router was superseded; Harness Router's own benchmark showed more tokens and time; gc.ai's useless-test detector was near coin-flip until decomposed; r6i's `path_score` could not separate correct from incorrect paths; JevLoop lost on wall clock and 8x on a trivial task; TypeSafeAI/jev-harness observed "no live recovery benefit". Criticism clusters on broad judgments, hard-question over-confidence, option-order sensitivity and "nudge, not a wall" recall.

### Cited Findings
- **Narrowed after a week**: jev-gates 0.9.0 — rule guard "interrupted far more often than it caught violations on real CLAUDE.md files"; scope guard "most in-scope edits scored near its threshold"; intent guard "+650 ms, edit asks were mostly on scratch files"; done and proof gates "most blocks landed on turns that were already fine" — [jev-gates](https://github.com/rashedInt32/jev-gates)
- **Dropped Jev from a feature**: hermes-jev-skills handoff digest 58.7% recall (75.0% with one search) vs plain transcript, scorecard 20 Sep — [hermes-jev-skills](https://github.com/kerpopule/hermes-jev-skills)
- **Features turned off in a mature plugin**: pi-warden 0.76.0 intent steer → trace-only; 0.78.0 relevance compaction off (reasons not stated on the page) — [pi-warden](https://github.com/DevMortimer/pi-warden)
- **Pre-screen removed**: jev-belay's keyword pre-screen caught only 41.7% of false dones; limpet's wording-only rule scored AUROC 0.50 on 1,500 stops and limpet itself reports 0.51–0.62 — [jev-belay](https://github.com/valentynkit/jev-belay); [limpet](https://github.com/noplan-inc/limpet)
- **Abandoned fine-tune**: Edward "a scorer fine-tune was attempted and abandoned under a pre-registered protocol" — [Edward](https://github.com/VeridicalTech/Edward)
- **Superseded / negative benchmark**: opencode-jev-router "superseded by reasoning-router" — [opencode-jev-router](https://github.com/robertn702/opencode-jev-router); Harness Router `BENCHMARK.md` "reports increased token usage and elapsed time" for the skill-driven Codex integration and "routing adds token and latency cost on obvious choices" — [harness-router](https://github.com/Protocol-Lattice/harness-router); JevLoop: hosted round trips made decisions 79% of wall clock, 5.9 s vs 3.4 s per task, and a rejected first draft cost 8x on a one-line task — [JevLoop](https://github.com/zjunlp/JevLoop)
- **Judge replacement that did not separate**: r6i's `path_score` rejected 1/50 vs 14 for the LLM judge, approved an out-of-taxonomy item at 0.65, "did not cleanly separate correct from incorrect paths"; greedy descent cannot backtrack — [blog.r6i.it](https://blog.r6i.it/typesafe-jev-vs-agentic-loop.html)
- **Broad questions fail**: gc.ai "is this test useless?" AUC 0.54 → 0.72 with eight factual questions; weekday-of-date 20% correct; array packing 96% → 72%; cookie banners captured as clauses — [gc.ai](https://gc.ai/blog/what-we-learned-building-38-projects-with-jev-in-12-hours); Every's rule of thumb and Sayora's literal-reading miss (water softeners → "none of these" at 96%) — [sayora](https://sayora.ai/many-hands/what-is-jev-good-for/)
- **Proposal review with no live benefit**: TypeSafeAI/jev-harness host-recovery run "observed no live recovery benefit"; initial live report "found lost tool use on multi-step tasks" — [TypeSafeAI/jev-harness](https://github.com/TypeSafeAI/jev-harness)
- **Hard-question over-confidence** (brussle, 1.14.0): hard-slice ECE 0.222 binary, 0.386 ordinal; no model calibrated on ordinal — [brussle](https://brussle.com/evals/calibration/)
- **Order sensitivity**: Zach Landes' trolley study (14 Oct, 5,240 setups; HN 428 points): changing only the order of track descriptions changed Jev's choice in 370 of 2,620 pairs; Jev saved twenty people over its own server in only 16 of 48 wordings; "a constrained choice set prevents hallucinated options but does not prevent a catastrophic option from being selected" — [zachlandes.com](https://zachlandes.com/trolley-problem/); simonw's photo-ranking failure with Decisions — [Ask HN](https://news.ycombinator.com/item?id=50072702)
- **General scepticism**: verdverm "Don't use decision models with important decisions" (coin-flip tests); lanyard-textile "scores are confidence levels, not probabilities"; bbor calls the marketing "borderline dishonest"; derefr: local inference makes shipping "much more complex" — [HN 1.14](https://news.ycombinator.com/item?id=50095353) [anecdotal]; Theo on compaction (text not retrieved) — [x.com/theo](https://x.com/theo/status/2100762304862384257) [anecdotal]
- **Threshold transfer failure**: tuned auto-merge threshold → 15 unsafe merges on 185 out-of-distribution cases — [awesome-jev-robustness](https://github.com/Yifan-Lan/awesome-jev-robustness)
- **Own-harness caveats stated by authors**: stepwarden "prompt injection aimed at the verifier is an open problem"; jev-firewall "Claude Code permission allow-lists can bypass hook decisions"; construct-auto-classifier "once it runs, the gate has no further say"; pi-jev-context "filtering can invalidate the model provider's prompt cache"; mu "no end-to-end comparison with pi, Claude Code, or Codex exists yet" — sources in KQ1

### Inferences
- The removals share a cause: a gate whose question is broader than the evidence available to it (CLAUDE.md rules, "in scope", "useless test", "digest this transcript") produces interruptions near the threshold; the gates that survived (claims-vs-tool-output, done-without-tests, destructive-command, wake-or-not) have a crisp evidence signal in the state. For a decision engine this argues for shipping shadow metrics per rule and refusing to enforce rules without an activation bar, as stingray and limpet already do.
- Latency, not accuracy, killed the "decision at every fork" designs (JevLoop, Harness Router) at ~300–400 ms hosted round trips; the viable designs either suppress asks in code (pi-warden, jev-belay) or run local heads (stuntd, Edward's 4B probe, pi-jev-eye's Clef-flash) at the cost of recall or quality.

### Gaps
- Reasons for pi-warden disabling relevance compaction and demoting the intent steer were not stated on the fetched page.
- No author published a before/after of user-visible productivity for any removed gate; all removals are justified by offline replay or author experience.
- The Theo and GoSailGlobal criticisms remain unretrieved.
