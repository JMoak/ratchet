# Jev deployments and composition patterns (TypeSafe AI "Jev", launched 15 Sep 2026)

Capture date for every source below: 2026-10-15 (all URLs fetched or surfaced via search on that date). Status tags used throughout:
- **[official]** = TypeSafe, or a vendor/partner describing its own integration (LangChain, Vercel, Workday, Langfuse, MLflow, DSPy maintainers).
- **[independent-with-code]** = third party with a public repo, notebook, or preregistered method and reported numbers.
- **[anecdotal]** = social post, demo video, press quote, or a write-up without code/method.

Background facts needed to read the catalogue: Jev exposes three primitives. **Noul** (named after Bernoulli per the CEO on HN) returns P(true) with no separate confidence; **Choice** picks one of 2–255 options and returns a probability distribution plus a confidence derived from the distribution's shape; **Score** returns an expected level on a 2–10 level rubric plus distribution and confidence. Many questions sharing one state run in parallel in one request; the shared budget is ~32K tokens; input costs $0.042 per million tokens and output is free — [rywalker.com review](https://rywalker.com/research/typesafe); [Langfuse docs](https://langfuse.com/docs/evaluation/evaluation-methods/jev-as-a-judge); [HN launch thread](https://news.ycombinator.com/item?id=49717558). TypeSafe's confidence field for Choice/Score "is derived from distribution shape... not an independent model judgment", and the Vals AI evaluation found it "tracks its probability distribution almost exactly and adds no extra signal" — [rywalker](https://rywalker.com/research/typesafe); [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev).

---

## Key question 1: What exactly did the named projects do and measure?

### Takeaway
Nearly every named deployment follows the same shape: code enumerates a bounded option set or a battery of yes/no checks, Jev answers all of them in one ~0.1–0.5 s call, and code applies thresholds/weights and escalates the rest. Measured gains are real but concentrated in latency (typically 3–25x in independent tests, 5–18x p95 at Vercel, 194x at 32 batched judgments in Vals' test) and cost (10–500x), while accuracy is usually at or slightly below cheap frontier models (TypeSafe's own board: 67.8% vs 74.1% for the best LLM; Vals: ties on claim verification, last of twelve on LegalBench). Several of the specific figures in the brief could not be located (see Gaps).

### Cited Findings

#### A. browser-use/jev-ultrafast (Gregor Zunic / Browser Use) — [independent-with-code]
- Jev decides one operation per step from CLICK, TYPE_TEXT, SELECT, SCROLL_UP, SCROLL_DOWN, WAIT, DONE, BLOCKED and one target element via "matching heads" (`click_target`, `type_text_target`, `select_target`); the state is an indexed element table like `[2] combobox Where from? · San Francisco`. Target questions are "speculative: the operation and target heads are answered in one request, and only the head matching the chosen operation executes." A small LLM (example: `inception/mercury-2.5` via OpenRouter) writes text only for TYPE_TEXT and must return parseable JSON. No screenshots in the default loop; model output never becomes selectors, coordinates, shell or JS — [GitHub README](https://github.com/browser-use/jev-ultrafast)
- Headline: Zürich→London on Google Flights in 7.1 s (video run 7,073 ms). Six alternating runs vs a screenshot baseline, both 3/3 passes: median task time 9.450 s → 7.092 s (25% reduction); median browser-protocol calls 1,092 → 101. Wikipedia article opened in 2.798 s; local hotel search in 1.896 s. README states the benchmark "is not a general reliability benchmark" — [GitHub README](https://github.com/browser-use/jev-ultrafast)
- Per-run cost $0.0039 (attributed to Jev's $42/billion input pricing) and the X demo video: [Inside.com.tw report](https://www.inside.com.tw/article/42431-jev-ultrafast-browser-agent-gregpr07); Zunic's post: https://x.com/gregpr07/status/2100411066966749359
- Trace detail from a third-party guide: the 7.073 s task used 17 Jev requests, 10 browser interactions, 1 wait, 2 text-generation calls, median Jev latency 178 ms — [Composio guide](https://composio.dev/blog/typesafe-jev-guide-and-best-practical-usecases)
- Stated limits: DONE needs independent outcome verification; shadow roots, frames, canvas, uploads, pop-up tabs, nested scrolling out of scope; the Flights example verifies the search but does not book. Repo stats at capture: 23.0k stars, MIT — [GitHub README](https://github.com/browser-use/jev-ultrafast)

#### B. LangChain: langchain-typesafe, AutoModeMiddleware, ModelRouterMiddleware, LangSmith evals — [official] + [independent critique]
- Launch post "Building a Harness with Jev" by Sydney Runkle and Hunter Lovell, 17 Sep 2026: `AutoModeMiddleware(tools=["bash"])` gates tool calls; `ModelRouterMiddleware` picks between "fast" (`openai:luna`) and "powerful" (`openai:sol`) from the latest user message with the instruction "Choose the least costly model that can complete the task." The example question is a Noul ("Does this need attention right now?"). No thresholds, no accuracy numbers, and the post does not contain a "5,000 requests for about $2" figure — [LangChain blog](https://www.langchain.com/blog/building-a-harness-with-jev)
- Docs: `TypeSafeClassifier` is a Runnable returning `nouls`, `choices`, `scores`; questions sharing state "run independently and in parallel in one request." AutoModeMiddleware hooks `wrap_tool_call`, "estimates the probability that a tool call is risky or insufficiently authorized," and on block returns an error `ToolMessage` instead of running the tool (no approval request). ModelRouterMiddleware hooks `before_agent` and `wrap_model_call`, classifies the latest human message across `ModelChoice(model=..., criteria=...)` entries, and uses the pick for every model call in the run. Requires `langchain-typesafe[experimental]` — [LangChain TypeSafe docs](https://docs.langchain.com/oss/python/integrations/providers/typesafe.md)
- LangSmith eval benchmark (Daniel Shea and Seán Roche, 20 Sep 2026; experiment started 2026-09-18): 5 frozen weather-agent runs × 100 repeats per judge = 500 decisions/judge. Jev: 100% agreement with the human oracle, mean quality-score variance 0.0000149, $0.00035/call, 0.44 s, $0.34 total. GPT-5.6 Luna 96.4%, variance 433x Jev's, $0.00039, 2.50 s. GPT-5.6 Terra 99.8%, 913x, $0.00289, 2.83 s. Claude Sonnet 4.6 80.0%, 92x, $0.02811, 2.16 s, $28.17 total. Caveats stated: five cases, one human reviewer, provider-default sampling params, Jev version not recorded, "low variance does not mean high accuracy" — [LangChain blog](https://langchain.com/blog/jev-agent-evals-langsmith); [jev-as-a-judge README](https://raw.githubusercontent.com/danielgshea/jev-as-a-judge/main/README.md)
- Later LangChain/LangGraph post (Sydney Runkle): Jev "5–6x faster than Sonnet on the page-classification step across trials"; LLMs handle "decisions Jev is unsure about" with no cutoff stated — [Digg summary linking x.com/sydneyrunkle/status/2103560531235795129](https://digg.com/ai/pcryg13z)
- Independent critique (Chew Loong Nian, 21 Sep 2026, reproduced against a local stub server): AutoModeMiddleware builds Jev's state from the last 30 messages, so "the explicit user message drops out around tool call 16"; the constructor defaults `criteria` to None and overwrites config defaults so Jev receives only a "risk criteria sent" flag; 429/503 fail the run immediately with no retry. Proposed fix: pin the newest user message into the classification state, pass criteria explicitly, retry outside the middleware — [Towards AI](https://towardsai.com/?p=53905)

#### F. Every (Mike Taylor, Dan Shipper, staff) — [anecdotal with described method]
- Mike Taylor, "Mini-Vibe Check" (15 Sep 2026, updated 7 Oct): 37 documents (27 Every articles + 10 AI-styled counterparts) × 21 yes/no "AI tell" questions = 777 judgments in under 0.7 s for ~$0.0025; across 11 experiments 1,709 judgments for under one cent. All 21 questions were asked "concurrently across all articles"; request structure and any reduce step are not described. Dan Shipper's linter test: 12 synthetic passages, 4 checks, 7 intended defects; Jev caught 6/7 (missed the "unexplained action" defect in all three runs), Fable 5.1 caught 7/7; median 0.35 s vs 8.83 s per passage (~25x), ~580x cheaper. Taylor "would want a more thorough accuracy check before production use" — [Every](https://every.to/vibe-check/mini-vibe-check-typesafe-s-jev-judged-everything-i-ve-written-in-0-7-seconds); corroborated by [rywalker](https://rywalker.com/research/typesafe)
- Every's workflow guide (Laura Entis, 23 Sep 2026): install TypeSafe's official skill; have a coding agent define the fuzzy term from your examples; split into discrete yes/no checks each with yes/no definitions, an example and a borderline case; decide in advance how to combine results and handle missing information; test blind against a small human-judged sample, then fresh examples. Reported outcomes: Douglas Brundage's bot reviewed <20 posts/run before Jev and >500 after; Jack Cheng's filter first "flagged newsletters as urgent" until criteria were revised; rule of thumb that tasks taking a human >~10 s need an LLM — [Every](https://every.to/context-window/how-to-get-the-most-out-of-jev)
- Every's DevDay 2026 Vibe Check vs OpenAI's Decisions API: on conversation-thread classification (Kieran Klaassen) accuracy effectively tied, Jev median 161 ms vs Decisions 309 ms; on a text-only computer-task replay (Jack Cheng) Decisions picked the correct control on 76/78 steps vs Jev 73/78 at ~230 ms vs ~500 ms — [Every](https://every.to/vibe-check/vibe-check-openai-devday-2026)

#### G. tamaratran/fast-jev-compaction (Claude Code plugin) — [independent-with-code]
- Two Noul questions per non-pinned tool call ("should the call stay", "should its result stay verbatim") against `keepThreshold` 0.5; outcomes: keep both, keep call with result truncated to 300 chars, or remove both. Questions are split across concurrent requests to keep state+questions under `maxRequestTokens` 30K; the full conversation state is resent with each request; tool results are replaced by size notes so Jev never sees result contents; token counts are character estimates. 7.7k stars, MIT — [GitHub](https://github.com/tamaratran/fast-jev-compaction)
- Author "kaize" (@0x_kaize, 18 Sep 2026): "1M tokens of context = ~$0.04 to compact"; claims "way faster/cheaper" than summarization with no benchmark; limits: Jev sees only tool calls not outputs, 32K window means 150K+ chats must be chunked, "proof of concept and a pre-filter" — [hermes-ai.net mirror of x.com/0x_kaize/status/2100913118528393596](https://hermes-ai.net/de/jev/case/2100913118528393596/)
- A Tencent engineering write-up reports a demo with 91.5% context reduction preserving file paths and error codes (secondary; the specific "1M → 86K" figure was not found in any fetched source) — [besthub tag page](https://www.besthub.dev/tags/fast-jev-compaction)

#### H. walidboulanouar/jev-agent-kit ("jevkit") — [independent-with-code, small sample]
- Tools and primitives: `check` (Noul), `choose` (Choice), `score` (Score), `judge` (several Nouls, passes only if all pass), `route` (Choice with abstention), `triage` (label selection), `guard` (allow/ask/deny second opinion), `grep` (per-line Noul), `rank` (Score ordering), `compact` (per-line relevance with pinned error lines + 1 line of context), `ask` (raw). Batching: 8 items/request for triage and rank, 12 lines for grep/compact, up to 4 concurrent requests. Fail-safe defaults: guard → ask, route → abstain, triage → null label, compact → keep line; exit code 1 = definite no, 3 = error — [GitHub](https://github.com/walidboulanouar/jev-agent-kit)
- Maintainer-run numbers (2026-09-20, `jev-latest`): guard flagged 15/15 risky shell commands and 0/15 routine ones (not tested on adversarial/obfuscated commands); compact on a 31-line build log with 12 relevant lines: model alone kept 58% of relevant lines, pinning without neighbours 100% (17 lines kept), defaults 100% (24 kept); grep matched 4 lines, all relevant, but found only 33% of relevant lines. README warns confidence is uncalibrated, rank scores are coarse, lines are judged in isolation so stack traces can be lost, and "adversarial text can steer" guard. 2 stars, MIT, sponsored by AY Automate — [GitHub](https://github.com/walidboulanouar/jev-agent-kit)

#### I. DSPy 3.4.0 Jev integration and ReAnchor — [official]
- `dspy.experimental.TypeSafe("jev-latest")` with output types `Noul` (`.value`, `.probability`, `.confidence`), `Choice[...]` (`.value`, `.probabilities`, `.confidence`), `Score[...]` (continuous `.value`, ordinal `.level`, `.probabilities`, `.confidence`), described as bringing "probability evidence into ordinary DSPy signatures." Decision rules (`assess.fields["urgent"] = {"threshold": 0.7}`) are applied locally, not sent to the backend, so identical requests reuse cached evidence; Score cuts change `.level` not `.value`. Noul confidence "measures distance from its threshold, not statistical calibration." Authors @isaacbmiller and @dbreunig, PR #10463 — [DSPy 3.4.0 release notes](https://newreleases.io/project/github/stanfordnlp/dspy/release/3.4.0)
- `dspy.experimental.ReAnchor(metric=...)` fits Boolean thresholds, Score cuts and Choice weights against the whole program's metric without touching instructions or demos. Candidates are midpoints between neighbouring observed probabilities (ties to the widest gap); a setting is accepted only if it improves training score and passes a 5-fold check (fit on 4/5, must also improve on the held-out 1/5). Reported calibration-only gains in the PR: email triage (1,000 unseen-sender test emails) 0.692 → 0.749; trend-report judge (8 test files) 0.813 → 0.874. Can also promote native `bool`/`Literal` outputs of generative LMs to probability evidence if calibration beats native behaviour. Merged 25 Sep 2026 — [DSPy PR #10475](https://github.com/stanfordnlp/dspy/pull/10475); [release notes](https://newreleases.io/project/github/stanfordnlp/dspy/release/3.4.0)

#### J. Langfuse and MLflow integrations — [official]
- Langfuse: evaluators hold 1–50 questions answered in one call; Choice stored as categorical score, Score as numeric expected level (e.g. 1.7 = "between level 1 and 2, closer to 2"), Yes/no as P(true); probabilities and confidence go to `metadata.typesafe`. Guidance: pick a cutoff (e.g. ≥0.7) or three bands "act, review, ignore"; add `other`/`unclear` Choice options because "Jev always picks an answer"; run Jev broadly then an LLM judge on a sample or flagged cases; pin `jev-1.13.0` "for stable thresholds". No accuracy numbers — [Langfuse docs](https://langfuse.com/docs/evaluation/evaluation-methods/jev-as-a-judge)
- MLflow (Yuki Watanabe, Databricks, 22 Sep 2026): `make_judge(model="typesafe:/jev-1.13.0", feedback_value_type=bool)` at a 0.5 threshold with probability in feedback metadata. On 30 human-labelled MLflow QA examples (15/15 after label correction): Jev 30/30, median 369 ms, p95 411 ms, $0.0247 per 1,000; GPT-5.6 Terra 30/30, 1,091 ms, $0.896; GPT-5.6 Luna 30/30, 947 ms, $0.0896; Claude Sonnet 4.6 27/30; Claude Opus 4.8 28/30 (p95 9,279 ms, $3.775); DeepSeek-V4.1-Flash 29/30. Recommends routing low-probability cases to another evaluator and using a Choice with "unsure" for abstention — [MLflow blog](https://mlflow.org/blog/jev-llm-judge)

### Inferences
- Where Jev matched or beat LLMs (LangSmith 500 decisions, MLflow 30, Near Here 50, Vals claim verification 400, Sniff Test), the task was a bounded classification on self-contained text with the answer set designed by the builder; where it trailed (invoice processing, LegalBench entailment, jevextract on legal NER, poker, Doom vs best LLMs) the task needed numeric reasoning, multi-hop inference, or long-tail label semantics — consistent with TypeSafe's own jaggedness list.

## Key question 2: Which composition patterns recur, and which have measured evidence?

### Takeaway
Nine patterns recur across the catalogue: batch-everything-per-state (incl. speculative fan-out), code-owned thresholds with labelled calibration, cascade/escalate-on-uncertainty, hard rules wrapping Jev (max(floor, jev) / deterministic ladders), shadow mode before enforce, cheap-retriever-then-Jev rerank or fusion, state pre-digestion (do arithmetic in code), split-fuzzy-into-weighted-checks, and option shuffling/rotation. Measured evidence exists for labelled thresholds (+0.06–0.09 F1, +0.057–0.061 metric), state pre-digestion (74.3% → 100% on 70 NPC scenarios), fusion (+0.090 NDCG@10 with CI), and confidence-based selective prediction (0.793 → 0.933 accuracy at 50% coverage); cascades were measured to save cost but add ≤2.7 points of accuracy because the fallbacks fail where Jev fails. Voting across rephrasings has no measured evidence for Jev; one paper found wording changes matter little (+0.006 AUROC).

### Cited Findings

**Pattern 1 — Batch every question per state; speculative fan-out**
- TypeSafe's definition: "a speculative question is one we ask before we even know if it's relevant," so for "Turn off all of the lights" four questions (request category, domain, device type, action) go in one batch and code discards irrelevant answers; sequential staging is "much slower and more expensive." Also: detect compound requests with one question, have an LLM split them, evaluate each atomic command; fall back to a conversational LLM for chit-chat — [TypeSafe smart-home demo docs](https://docs.typesafe.ai/demos/smart-home)
- Vendor measurements: 13 questions in one call ~11.5x cheaper and ~9.6x faster than one at a time; cookbook 12.2x/10.0x (timing sums sequential calls) — [kingy.ai](https://kingy.ai/?p=931053). Independent: Vals saw Jev latency stay at ~0.10–0.12 s from 1 to 64 judgments on one document — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev). "Just Ask Jev" calls carried 11.4 questions on average at 0.31 s median — [arXiv 2609.29429](https://arxiv.org/html/2609.29429)
- Used by: jev-ultrafast (operation + all target heads in one request); jevmail (3 questions/message); jev-mailroom (11/call); hermes-jev-approvals (6/command); pi-warden (4/command); Mike Taylor (21 questions × 37 docs); fast-jev-compaction (2 Nouls per tool call, chunked to stay under 30K tokens) — sources as cited in KQ1.

**Pattern 2 — Code owns thresholds and weights; calibrate on labelled examples**
- Vercel's guidance: "calibrate probabilities and confidence against labeled examples from your workflow" — [search summary of Vercel docs](https://vercel.com/changelog/typesafe-ai-jev-now-available-on-ai-gateway). DSPy applies thresholds/cuts/weights locally so cached evidence is reused — [DSPy 3.4.0](https://newreleases.io/project/github/stanfordnlp/dspy/release/3.4.0)
- Measured: ReAnchor's fold-checked threshold/cut/weight fitting raised email triage 0.692 → 0.749 (1,000 unseen-sender test emails) and a trend-report judge 0.813 → 0.874 — [DSPy PR #10475](https://github.com/stanfordnlp/dspy/pull/10475). "Just Ask Jev": median F1-optimal threshold is 0.35, not 0.5; fitting on just 10 labelled items raised median F1 from 0.706 (t=0.5) to 0.793; 2-fold CV threshold 0.822 (SD 0.022 across 20 fold seeds); oracle 0.849; a label-free prior-shift correction did not help — [arXiv 2609.29429](https://arxiv.org/html/2609.29429). DoGMaTiiC's gate/fits sweep found a knee at gate 0.25–0.30 with fits flat across 0.30–0.45 — [Hermes docs](https://hermes-agent.nousresearch.com/docs/plugins/jev-skill-router)
- Labelled bands rather than a single cutoff: Langfuse "act, review, ignore"; ten-levels Level 4 (below 0.5 human decides, above 0.9 destructive action runs unconfirmed); jev-shield review 0.35 / action 0.7 / severity_block 2.0; Composio examples (confidence <0.5 → manual triage; urgency >0.8 + technical → severity queue; moderation remove 0.8 / review 0.5) — [Langfuse](https://langfuse.com/docs/evaluation/evaluation-methods/jev-as-a-judge); [ten-levels](https://github.com/disler/ten-levels-of-jev); [jev-shield](https://github.com/caiovicentino/jev-shield); [Composio](https://composio.dev/blog/typesafe-jev-guide-and-best-practical-usecases)

**Pattern 3 — Cascade / escalate-on-low-confidence to a frontier model or human**
- Recommended by MLflow (route low-probability cases; Choice with "unsure" for abstention), Langfuse (LLM judge on sample/flagged cases), LangChain (LLMs handle "decisions Jev is unsure about"), Lindfors (accept high-confidence, send uncertain to a slower model or person) — [MLflow](https://mlflow.org/blog/jev-llm-judge); [Langfuse](https://langfuse.com/docs/evaluation/evaluation-methods/jev-as-a-judge); [Digg/LangChain](https://digg.com/ai/pcryg13z); [lindfors.no](https://lindfors.no/blog/a-first-look-at-typesafes-jev/)
- Measured, confidence-based selective prediction works: keeping the half of decisions with the largest |p−0.5| raised median accuracy from 0.793 to 0.933 — [arXiv 2609.29429](https://arxiv.org/html/2609.29429). Vals (1% error budget, threshold set on 30%, tested on 70%): Jev automated 95% at 1.6% realized error (over budget; in hindsight 91% within budget); routing 1% of claim cases to Astra matches Astra at $0.27 per 1,000, but Luna alone matches at $0.08; on LegalBench Jev must defer 64% and saves only 18% while routing through Sol saves 72% — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev)
- Measured, cascades add little accuracy: Rao and Callison-Burch found a decision-model-first stage with LLM fallback gained at most 2.7 points over the strongest single judge even with oracle thresholds, and a higher-tier fallback no more than 1.7 points, "because the fallbacks fail where the first stage fails"; >85% of flash-tier verdicts on Jev's most confident errors repeat those errors (independent errors would give ~50%) — [arXiv 2609.29769](https://arxiv.org/abs/2609.29769). jev-guardbench implements a Jev→Gemini cascade but reports only per-guard F1 — [GitHub](https://github.com/dfranco-projects/jev-guardbench)
- Lindfors' calibration bins support the mechanism: stance agreement 14/15 at top-probability ≥0.9 vs 6/9 below; respondent 20/20 vs 1/3 — [lindfors.no](https://lindfors.no/blog/a-first-look-at-typesafes-jev/)

**Pattern 4 — Hard rules wrap Jev: deterministic floor/ladder, Jev only as a signal**
- hermes-jev-approvals applies an ordered deterministic ladder over six typed answers before trusting the model's own verdict — [GitHub](https://github.com/anpicasso/hermes-jev-approvals). jev-shield: structural rules (allowlists, required flags) run deterministically and free; Jev adds semantic probability; `hazard_actions` map to block in `config/policies.json` "rather than in prompts" — [GitHub](https://github.com/caiovicentino/jev-shield). pi-jev-auto-mode: "hard-deny commands never reach Jev" — [search summary](https://pi.dev/packages/pi-jev-auto-mode). jev-ultrafast: "model output never becomes selectors, coordinates, shell commands, or JavaScript"; executor rechecks freshness and occlusion — [GitHub](https://github.com/browser-use/jev-ultrafast). jevkit guard "never returns allow" in hook mode; `compact` pins error-looking lines and keeps a neighbour — [GitHub](https://github.com/walidboulanouar/jev-agent-kit)
- Measured: jevkit compact on a 31-line log kept 58% of relevant lines with the model alone, 100% once error lines were pinned (with or without neighbour context) — [GitHub](https://github.com/walidboulanouar/jev-agent-kit). Projeckt AI's recommendation: "pairing Jev with deterministic checks, calibrating thresholds on your own labels, and keeping tool output out of the classifier's input" — [Projeckt AI](https://projecktai.substack.com/p/jev-claims-193x-faster-444x-cheaper)
- No source used the literal expression `max(floor, jev)`; the closest are pinning (jevkit), hard-deny lists (pi-jev-auto-mode), and "truncated commands are never auto-approved" (hermes-jev-approvals).

**Pattern 5 — Shadow mode before enforcement; fail-open vs fail-closed**
- DoGMaTiiC jev-judge defaults to `shadow` (log only) with `enforce` opt-in and is "fail-open on every error path" — [Hermes docs](https://hermes-agent.nousresearch.com/docs/plugins/jev-judge). Shimomoto ran his router in shadow (logging picks without feeding them to Claude Code) for a week before deciding to remove it — [dev.to](https://dev.to/shimo4228/is-there-any-point-to-this-removing-the-jev-plugins-i-added-to-claude-code-after-one-week-49eh). jev-shield `fail_mode` open by default, closed available — [GitHub](https://github.com/caiovicentino/jev-shield). Counter-example: LangChain's AutoModeMiddleware fails closed on 429/503 with no retry — [Towards AI](https://towardsai.com/?p=53905). No source measured shadow-vs-enforce outcomes.

**Pattern 6 — Cheap retriever first, Jev to rerank or as a fused second signal**
- Simon Willison: BM25 ~100 candidates then Jev scores each — [simonwillison.net](https://simonwillison.net/2026/Sep/21/jev). Measured (zhuyansen, 33,047-entry catalog, 164 queries, 9,831 labelled pairs, `score` rerank of top-30 in one call per query): Jev rerank alone NDCG@10 0.785 vs bge-m3 0.774 (Δ +0.012, CI [−0.013, +0.037], not significant; under LLM-only labels Δ −0.028) but MRR 0.872 → 0.953; **RRF fusion of bge-m3 and Jev: 0.864 (Δ +0.090, CI [+0.077, +0.104]; +0.064 under LLM-only labels)**; ~$0.0002 per rerank call. Judge circularity quantified: same comparison reads +0.053 under Jev-only labels and −0.028 under LLM-only — [GitHub](https://github.com/zhuyansen/jev-search-rerank-eval). LlamaIndex Jev reranker: nDCG@5 on nfcorpus 0.340 → 0.396 at ~$0.0003/query — [HackerNoon](https://hackernoon.com/101-real-world-examples-of-how-to-use-jev)

**Pattern 7 — Pre-digest the state in code (arithmetic, dates, counts, pruning)**
- TypeSafe's own fixes: count in code with one yes/no per item; extract date parts as a Choice and do arithmetic in code — [jaggedness docs](https://docs.typesafe.ai/model-jaggedness/jev-1.13). Measured (suranjaychandra/jev-state, 70 NPC scenarios, 7 actions, same instructions and options): raw state 74.3% → 100% when code bands numbers into labels ("critical" instead of `hp: 38, maxHp: 250`), converts timestamps to relative labels and prunes irrelevant fields; unstable scenarios 6/70 → 0/70; input tokens 1,236 → 699 (−43%); p50 336 vs 335 ms; raw-state accuracy was weakest on arithmetic rules (retreat 50%, patrol 43%); 420 calls, $0.017 — [GitHub](https://github.com/suranjaychandra/jev-state). backnotprop pre-computed pot odds, SPR and outs in Python so Jev did no arithmetic — [backnotprop](https://backnotprop.com/blog/jev-poker/)

**Pattern 8 — Split a fuzzy judgment into discrete weighted checks, combine in code**
- Every's guide (yes/no checks each with definitions, example and borderline case; code combines) and Jack Cheng's weighted ranking — [Every](https://every.to/context-window/how-to-get-the-most-out-of-jev). ten-levels Level 3 composite scoring with weights {0.6, 0.3, 0.1} — [GitHub](https://github.com/disler/ten-levels-of-jev). jev-guardbench's "Jev decomposed" variant — [GitHub](https://github.com/dfranco-projects/jev-guardbench). Shimomoto's four-step Overlap ladder plus a "different problem" escape option — [dev.to](https://dev.to/shimo4228/moving-my-research-pipelines-judgment-calls-from-an-llm-to-jev-a-judgment-only-model-4ncj)
- Measured caution: "Just Ask Jev" found rubrics that threshold each sub-answer at 0.5 lost to the best single targeted question on 9 of 10 benchmarks (median −0.137 AUROC), while a 3-level Score read as an expected level beat the generic Noul on 19 of 31 benchmarks and argmax readouts "lose almost everywhere" — [arXiv 2609.29429](https://arxiv.org/html/2609.29429). HackerNoon cites a judge-vs-dimension-scores comparison of 0.9076 vs 0.8373 on Japanese NLI but with ~25x more hard benign rows flagged (source page not retrieved) — [HackerNoon](https://hackernoon.com/101-real-world-examples-of-how-to-use-jev)

**Pattern 9 — Option shuffling / cyclic rotation against position bias; escape options**
- TypeSafe: "reordering options to check consistency" — [jaggedness docs](https://docs.typesafe.ai/model-jaggedness/jev-1.13). Measured: imaddde867 reordered a 3-option enum three ways over 6 messages; hosted jev-1.13.0 changed 0/6 labels (36 answers) on 20 Sep and again on 3 Oct, but confidence spread across orderings was 0.13–0.16 vs ≤0.04 between identical repeats; the local MLX clone changed 5/6 (14 of 18 answers were the second-listed option) — [GitHub](https://github.com/imaddde867/jev-position-test). AnyJev (not Jev) evaluates all cyclic rotations and log-mean-pools; on Qwen3-8B/BANKING77 answer-flip rate under reversal fell 23.0% → 7.3% and ECE 0.240 → 0.095 with temperature scaling — [wavect.io](https://wavect.io/blog/anyjev-calibration-option-order-bias/). ContractNLI study: changing only output order changed 14/90 Claude Haiku responses (−11 points) — [redreamality](https://redreamality.com/blog/jev-vs-llm-contractnli-same-scores-different-decisions/)
- Escape options: Langfuse and MLflow recommend `other`/`unclear`/`unsure`; jevkit `route` abstains; jevextract asks "or none"; Shimomoto needed a "different problem" rung — sources above.

**Pattern 10 — Voting across rephrasings / ensembles**
- No source measured Jev ensembles or majority voting across rephrasings. "Just Ask Jev" compared wordings and found the best targeted question beat the best generic readout by only +0.006 AUROC out of sample (CI −0.004 to +0.015) — [arXiv 2609.29429](https://arxiv.org/html/2609.29429). backnotprop tried five phrasings over 30 poker spots and found value-laden wording pushed Jev toward bigger bets, so neutral labels were used — [backnotprop](https://backnotprop.com/blog/jev-poker/). Lindfors found longer, more qualified questions raised calibration error from 0.040 to 0.116 and slightly lowered agreement (0.89 → 0.86) — [lindfors.no](https://lindfors.no/blog/a-first-look-at-typesafes-jev/)

**Pattern 11 — Jev as hook vs Jev as agent tool; evaluate in fixed pipelines**
- ten-levels contrasts silent hooks (Levels 6–7) with agent-callable tools (8–10) — [GitHub](https://github.com/disler/ten-levels-of-jev). Shimomoto: "a judgment model is easy to evaluate in a fixed pipeline... In agent loops... adding a component can change downstream behavior in hard-to-see ways"; suggests designing the flow around Jev from the start or using it only inside fixed pipelines — [dev.to](https://dev.to/shimo4228/is-there-any-point-to-this-removing-the-jev-plugins-i-added-to-claude-code-after-one-week-49eh)

### Inferences
- The strongest measured levers are upstream of the model: labelled thresholds, state pre-digestion, and fusion with an embedding retriever each moved metrics by 5–25 points, whereas cascading to a bigger model bought ≤2.7 points because errors are correlated. This suggests effort is better spent on question/state design and threshold calibration than on fallback models.
- Hosted Jev appears materially more order-stable than open clones, but its probabilities still drift with order (0.13–0.16 spread), so option rotation is justified when thresholds sit near the decision boundary even if labels look stable.
- "Shadow mode" is standard practice in the guardrail plugins but nobody published shadow-vs-enforce outcome data; the one week-long shadow run that was published (Shimomoto) led to removal, which argues for making shadow logging a required step.

### Gaps
- No measured comparison of a Jev ensemble (multiple calls, rephrasings, or rotations) to a single call on hosted Jev.
- No published shadow-mode → enforce transition data (false-positive rates before/after).
- The `max(floor, jev)` pattern as a named construct was not found; only analogous pinning/hard-deny implementations.
- The "Japanese NLI 0.9076 vs 0.8373" dimension-score comparison's primary page (agentjournal.dev) could not be located.

## Key question 3: What failure modes did real users hit?

### Takeaway
Users hit every failure mode TypeSafe lists in its jaggedness doc plus several deployment-level ones: prompt/evidence injection flips verdicts (Check Point 59% break rate, ~$0.50 per break; "pre-approved" note dropped P(block) 0.76 → 0.48), literal reading of questions (HN home-assistant example; first-draft filters flagging newsletters), numeric/date weakness (poker shove with the nuts; NPC rules at 43–50% on raw numbers), yes-bias on legal entailment (33/33 "Yes"), context rot and the 32K/30-message windows (AutoMode forgetting the user at tool call 16), irrelevant suggestions in agent loops (5% uptake), rate limits and a signup pause in week one, and over-confident probabilities on extraction (ECE 0.17–0.44).

### Cited Findings
- **Vendor-documented jaggedness (jev-1.13):** literal reading ("answers the question you wrote, not the one you meant"); unreliable counting that worsens with list size; "Jev is not a calculator" (hex colours, RGB triples, assembly underperform); Score levels "weak in numerical calibration" for interpolation; dates read "as text, not as ordered quantities"; double negatives and multi-hop weaker; "context rot" as unrelated state grows; adversarial content "does not treat it as hostile by default"; contradictory instructions (a Noul where true maps to no performs worse); position bias ("leans toward the option that comes first"); forced generation via chained choices "slow and works poorly" — [TypeSafe jaggedness docs](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
- **Prompt/evidence injection:** Check Point (24 Sep 2026) built a due-diligence assistant on Jev; three agentic attackers × 3 difficulty levels × 3 runs: strongest attacker broke 25/27 configurations at ~$0.50 per break, succeeding by turn four on average; the winning technique appended a plausible audit addendum with "no instructions to the model"; typed input and an "untrusted" marker made no meaningful difference (16 vs 16 vs 13 breaks of 27); explicit anti-injection instruction moved breaks from 18 to 17 of 27 ("noise"); longer evidence helped; reasoning was the strongest defense on other models but "Jev has no reasoning setting"; Jev's overall success rate 59% vs Model I no-reasoning 100%, Model II with reasoning 19% at $4.39/break — [Check Point blog](https://blog.checkpoint.com/ai-security/jev-is-not-a-language-model-but-it-breaks-like-one-prompt-injection-against-a-typed-decision-model/)
- Decision Hijacking (Wu and Lim, 23 Sep 2026; 510 reconstructed InjecAgent cases, three-option Choice): base attack selected the attacker target in 9/510 (1.8%), enhanced override-prefix attack 0/510; base attack raised attacker-target probability by +0.043 and lowered safe-action probability by 0.084; adaptive attacks with score feedback raised validated success to 3.5%; near-boundary margins (≤0.1) succeeded 12/12 vs far-boundary 1/468; "IMPORTANT!!!" and ignore-previous markers reduced attacker probability — [arXiv 2609.28613](https://arxiv.org/html/2609.28613)
- Don Karter (Muvon) test: a fake "pre-approved" field moved P(block) on `rm -rf ~/.ssh` from 0.76 to 0.48 and confidence from 0.64 to 0.22 — [Projeckt AI](https://projecktai.substack.com/p/jev-claims-193x-faster-444x-cheaper); [NeuralTrust (citing VentureBeat 21 Sep)](https://neuraltrust.ai/es/blog/jev-typesafe-ai-security). ten-levels author: an agent bypassed a single-gate block by writing a file through a bash heredoc; blocks are "an instruction, not a control" — [GitHub](https://github.com/disler/ten-levels-of-jev). jevkit, jev-shield, hermes-jev-approvals and NeuralTrust all state Jev is "not a security boundary"/"a reviewer, not a sandbox" — sources in KQ1
- **Literalness and framing:** HN home-assistant example answered "Yes" to a "human agent" question ignoring timing until a time-based choice was added — [HN launch thread](https://news.ycombinator.com/item?id=49717558). Jack Cheng's first email filter flagged newsletters as urgent — [Every](https://every.to/context-window/how-to-get-the-most-out-of-jev). Shimomoto's router "reacted to agent-written text (such as subagent messages) as if the user had written it"; jev-belay only recognised known tool names so a project `verify.sh` didn't count as verification — [dev.to](https://dev.to/shimo4228/is-there-any-point-to-this-removing-the-jev-plugins-i-added-to-claude-code-after-one-week-49eh). Lindfors classed two private persons as organisations, one from a three-sentence letter — [lindfors.no](https://lindfors.no/blog/a-first-look-at-typesafes-jev/)
- **Numeric weakness:** poker: with the nuts on a no-flush board Jev shoved 62% (CI 59–65%) where the solver checked 100%, and shoved 16/16 runs; overall 63% agreement with solver top action over 30 spots — [backnotprop](https://backnotprop.com/blog/jev-poker/). NPC rules depending on arithmetic scored 50% (retreat) and 43% (patrol) on raw numbers — [jev-state](https://github.com/suranjaychandra/jev-state). Vals: all twelve systems including Jev scored 1.00 on numeric-discrepancy claim items, so the weakness is task-dependent — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev)
- **Yes-bias / class collapse:** on `contract_nli_permissible_copy` Jev answered "Yes" to all 33 items (gold 16/17) and yes to 30/33 on confidentiality-of-agreement, while LLMs scored 0.91–1.00 — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev). jevextract: Jev's misses were "genuine matches it under-rated" at the 1↔2 boundary; the search-rerank judge disagreement was 1,768 pairs — [jev-search-rerank-eval](https://github.com/zhuyansen/jev-search-rerank-eval)
- **Context windows and irrelevant context:** AutoModeMiddleware's 30-message window drops the user request around tool call 16 — [Towards AI](https://towardsai.com/?p=53905). fast-jev-compaction must chunk 150K+ chats and re-sends full state per request — [GitHub](https://github.com/tamaratran/fast-jev-compaction). Norwegian tokenises at ~2.06 chars/token so the 32K budget is ~64K characters — [lindfors.no](https://lindfors.no/blog/a-first-look-at-typesafes-jev/). jevkit: "irrelevant text in the state reduces accuracy" — [GitHub](https://github.com/walidboulanouar/jev-agent-kit)
- **Low-value suggestions in agent loops:** 28 of 539 skill picks used (~5%); 13 of 20 reviewed unused picks off target — [dev.to](https://dev.to/shimo4228/is-there-any-point-to-this-removing-the-jev-plugins-i-added-to-claude-code-after-one-week-49eh)
- **Rate limits, outages, signup pause:** TypeSafe paused new signups at 06:19 UTC on 22 Sep 2026 after opening public access on 20 Sep; existing accounts kept working; reported limits conflict (250K tokens/s and 1,200 RPM vs 100K tokens/s and 80 RPS) — [flaviocopes.com](https://flaviocopes.com/jev-api-key/); [opentweet limits page](https://opentweet.io/jev/limits). TechCrunch: the company "briefly lost the ability to serve API users because of high demand" — [TechCrunch](https://techcrunch.com/2026/09/18/a-new-kind-of-ai-model-from-a-chatgpt-inventor-is-thrilling-developers/). Plugins added 429/529 handling: one retry if Retry-After ≤2 s then 120 s silence (DoGMaTiiC); 20 s timeouts with retries so an outage takes ~a minute to surface (jevkit); free Vercel Gateway tier of 5 calls per 5 minutes (jevmail) — sources in KQ1
- **Opacity / no rationale:** MLflow, Langfuse, Simon Willison all flag that Jev returns only a number so debugging and bias isolation are hard — [MLflow](https://mlflow.org/blog/jev-llm-judge); [Langfuse](https://langfuse.com/docs/evaluation/evaluation-methods/jev-as-a-judge); [simonwillison.net](https://simonwillison.net/2026/Sep/21/jev). HN and The Register: "zero hallucination" means schema validity only — [HN thread](https://news.ycombinator.com/item?id=49717558); [The Register](https://www.theregister.com/a/5298431)
- **Run-to-run instability near boundaries:** jevextract two full runs agreed at Jaccard 0.86–0.97 with borderline decisions changing — [GitHub](https://github.com/gabazureus/jevextract). ContractNLI: Jev kept 23/30 anchors correct across all conditions vs 18/30 for Qwen3.5-9B, but five of Jev's consistent anchors were "stable wrong" — [redreamality](https://redreamality.com/blog/jev-vs-llm-contractnli-same-scores-different-decisions/). Vals: Jev gave the same answer on all five repeats of 25 items — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev)
- **Non-English:** TypeSafe says English is primary and CJK "not on equal footing" — [search summary](https://dev.classmethod.jp/articles/litellm-deepeval-jev/)

### Inferences
- The injection results show the vulnerability is to plausible *evidence*, not just to instructions, which is why structured input and "untrusted" markers did nothing; mitigations that worked (more evidence, pre-screening inputs, hard-deny lists, high-margin thresholds) all live outside the model.
- Decision margin is the operational signal: Decision Hijacking's 12/12 vs 1/468 split and the position-test's 0.13–0.16 probability drift both say decisions within ~0.1 of the threshold are the ones that flip, so builders should widen the review band rather than trust a single cutoff.

### Gaps
- No user reported calibration drift across model versions (jev-1.12 → 1.13) despite several pinning `jev-1.13.0` "for stable thresholds"; the position-test rerun found identical labels 13 days apart.
- The Check Point per-configuration raw logs and the VentureBeat article behind the 0.76 → 0.48 figure were not fetched.

## Key question 4: Did anyone measure calibration directly, or compare ensembles to single calls?

### Takeaway
Yes on calibration, no on ensembles. Four independent groups computed ECE on hosted Jev and the results span 0.011 (Vals claim verification) to 0.17–0.44 (jevextract), with "Just Ask Jev" showing pooled ECE 0.047 but per-benchmark median 0.168 driven by base-rate mismatch rather than bad ranking; Lindfors drew informal reliability bins showing monotonic but under-confident behaviour. TypeSafe publishes no calibration numbers. No one compared ensembles of Jev calls to single calls; the only related evidence is that question wording barely matters (+0.006 AUROC) and that cascades to LLMs add ≤2.7 points.

### Cited Findings
- **Vendor:** TypeSafe's launch post gives no quantitative calibration results, only that "higher confidence means higher accuracy" — [TypeSafe launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev). Confidence for Choice/Score is derived from distribution shape and "0.9 should not be read as a measured 90% success rate"; calibration "applies to groups of predictions" — [rywalker](https://rywalker.com/research/typesafe). DSPy: Noul confidence "measures distance from its threshold, not statistical calibration" — [DSPy 3.4.0](https://newreleases.io/project/github/stanfordnlp/dspy/release/3.4.0)
- **Vals AI (preregistered, 12 systems):** Jev ECE 0.011 on claim verification (lowest of twelve) but 0.108 on LegalBench (highest); "calibration on one benchmark did not transfer to the other"; Jev's `confidence` adds no signal beyond the probability; selective prediction at a 1% error budget: 95% automated at 1.6% realized error; Brier and reliability diagrams not reported — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev)
- **"Just Ask Jev" (Guo et al., 24 Sep 2026; 44 benchmarks, 10 failure types, jev-1.13.0, single generic Noul):** pooled reliability curve close to diagonal (ECE 0.047); per-benchmark median ECE 0.168 vs 0.074 null under perfect calibration, 24/31 benchmarks exceed the null's 95th percentile; attributed to base-rate mismatch (median gap between mean probability and positive rate 0.125) not ranking (median AUROC 0.905); median F1-optimal threshold 0.35; reliability diagrams in Appendix E; no Brier scores in the visible text; median AUROC 0.886 (CI 0.821–0.952); 63x cheaper than LLM judges pooled ($0.30 vs $18.96 per pass); about 25% of remaining disagreements are Jev errors — [arXiv 2609.29429](https://arxiv.org/html/2609.29429)
- **Lindfors (24 docs, 192 argument judgments):** low-probability bins had few reference "yes" labels, high bins almost all; "somewhat underconfident at both ends"; wording change moved calibration error 0.040 → 0.116; DeepSeek with reasoning was less calibrated mid-range — [lindfors.no](https://lindfors.no/blog/a-first-look-at-typesafes-jev/)
- **jevextract:** ECE 0.17–0.44, "over-confident" — [GitHub](https://github.com/gabazureus/jevextract). **jev-state:** raw-state answers rated 70–90% were right 81% of the time ("reasonably calibrated") — [GitHub](https://github.com/suranjaychandra/jev-state). **jev-plays-pokemon-red:** scores each battle-turn faint prediction by Brier against RAM state (no figures surfaced) — [awesome-jev README](https://raw.githubusercontent.com/hellogumbo/awesome-jev/main/README.md)
- **Rao and Callison-Burch:** each decision model's confidence "ranks its errors on most ordinal panels" (i.e., useful for selective prediction) but no ECE given in the abstract; decision models and LLM judges "agree more with each other than with human labels on ordinal criteria" — [arXiv 2609.29769](https://arxiv.org/abs/2609.29769)
- **Secondary/unverified ECE figures:** a pentest-harness paper reportedly cites "TypeSafe reports ECE of 0.246 for Jev on their own evaluation set" (reference not retrievable from the PDF; no TypeSafe page with that number was found) — [arXiv 2609.28940](https://arxiv.org/abs/2609.28940); a "Xenospectrum" phishing benchmark giving Jev ECE 0.154 vs Haiku 0.097 at 239 ms vs 687 ms is cited by Projeckt AI but the primary was not found — [Projeckt AI](https://projecktai.substack.com/p/jev-claims-193x-faster-444x-cheaper)
- **Consistency as a proxy:** LangSmith's 500-decision runs: Jev quality-score variance 0.0000149, 92–913x lower than LLM judges, with "repeatable is not the same as correct" — [LangChain](https://langchain.com/blog/jev-agent-evals-langsmith). Vals: identical answers on 5/5 repeats of 25 items — [Vals AI](https://www.vals.ai/blogs/independent-evaluation-of-jev). Position test: ≤0.04 probability change between identical repeats — [GitHub](https://github.com/imaddde867/jev-position-test)
- **Upcoming:** a Maven session "Can You Trust Jev's scores?" (4 Nov 2026) plans to pool 113 labelled yes/no answers across three tasks and draw reliability diagrams for Jev vs Claude self-reported confidence — course listing, not results — [Maven](https://maven.com/p/42d41c/can-you-trust-jev-s-scores)
- **Ensembles vs single calls:** not evaluated in "Just Ask Jev" — [arXiv 2609.29429](https://arxiv.org/html/2609.29429); not in Vals; Rao and Callison-Burch evaluated cascades, not Jev-only ensembles — [arXiv 2609.29769](https://arxiv.org/abs/2609.29769); AnyJev's rotation pooling was measured only on Qwen models — [wavect.io](https://wavect.io/blog/anyjev-calibration-option-order-bias/). Thresholded sub-question rubrics underperformed one well-targeted question (median −0.137 AUROC) — [arXiv 2609.29429](https://arxiv.org/html/2609.29429)

### Inferences
- Jev's probabilities rank well (AUROC ~0.9, confidence orders errors) but are not absolutely calibrated per task — the base rate shifts the whole curve — so a per-task threshold fit on ~10–30 labelled items (ReAnchor, "Just Ask Jev") is the cheapest fix and is already the de facto practice in the better plugins.
- Because Jev's run-to-run variance is near zero, self-consistency ensembles of the same question cannot add information the way they do for sampled LLMs; the only ensemble lever left is diversity in question framing or option order, and the single study of wording found ~no gain.

### Gaps
- No Brier scores on hosted Jev were found in any fetched source.
- No reliability diagram with bins was published outside the "Just Ask Jev" appendix (not fetched) and Lindfors' informal bins.
- No measurement of ensembles/rotations/rephrasings vs single calls on hosted Jev.
- TypeSafe's own calibration data (the "RLCD" training claim and any ECE) remains unpublished; the 0.246 figure is unverified.
