## Key question 1: Threshold and calibration learning (ReAnchor internals; Platt/isotonic; base rates; tiny label sets; conformal; margin bands; label-free estimation; drift)

### Takeaway
Six independent groups now agree that hosted Jev's raw probabilities rank well (AUROC 0.83–0.93) but are not absolutely calibrated on any particular user's distribution (raw ECE 0.06–0.21 on real labelled data, 0.01–0.04 only on synthetic deterministic tasks); isotonic regression on a few hundred labels brings ECE to ~0.01, Platt to ~0.05, and 20–100 labels already halve the error. ReAnchor's source shows a fully specified, reimplementable procedure (midpoint candidates from observed probabilities, ≤40 per step, coordinate descent per label/cut, deterministic 5-fold "pick on 4/5, sum on 1/5" acceptance, strict improvement required). Conformal abstention on hosted Jev exists only in one small local clone (poorjev); nobody has published CBPE-style label-free accuracy estimation on Jev; drift tooling is CI-style replay (jevcal `check`) or rolling agreement against a teacher (stuntd).

### Cited Findings

**A. DSPy `ReAnchor` — the reference threshold/cut/weight fitter [official, source read]**
- Source file `dspy/teleprompt/reanchor/calibrate.py`: `calibrate(program, trainset, metric, num_threads=None)`; constants `MAX_CANDIDATES = 40`, `WEIGHT_RANGE = (1e-3, 1e3)`, `FOLDS = 5` (one fold per example when n < 5); no minimum example count. Traversal is **sequential, not joint**: `predictors(program)` yields each `Predict` with a decision output; each field is fitted in turn; inside a Choice or Score field, **coordinate descent** runs over individual labels or cut points, and an accepted move updates the baseline before the next. Metric: `scores` runs the program on every example via `ParallelExecutor(max_errors=1)` inside `dspy.context(trace=[])`, raising on non-finite values; every candidate is scored on the full trainset. Candidate generation `_gaps(values, lo, hi, geometric=False)`: keep distinct observed values strictly inside (lo, hi), thin to evenly spaced quantiles if more than 39, close with lo and hi, return (midpoint, width) per gap (geometric midpoints `sqrt(a*b)` with width `log(b/a)` for weights); `_tidy` rounds each midpoint to the shortest decimal (≤11 digits) still inside its gap. **Thresholds** (`_fit_threshold`): gaps over observed P(True) in (0,1); adjacent floats get the upper value; zero added if observed. **Cuts** (`_fit_cuts`): per call mean level index `sum(i*p)/sum(p)`; cut i bounded by neighbours (0 … len(criteria)−1); candidates are midpoints of means inside those bounds. **Weights** (`_fit_weights`): per label, a "flip" is the multiplier where that label's weighted probability equals its strongest rival's (`rival / p[label]`); range `[min(flips)/4, max(flips)*4]` clipped to WEIGHT_RANGE; geometric midpoints between flips. **Ties** (`_pick`): max by total held-out score, then widest gap; thresholds additionally prefer closest-to-start then larger value. **Fold check** (`_folds(n)`): indices shuffled with `random.Random(0)`, round-robin `order[i::k]`, k = min(5, n); per fold, pick the best candidate on the other folds (fallback: start); held-out score = sum of per-example metric across folds for each fold's pick vs `held_start`; accept only if `held > held_start` strictly **and** the candidate beats start strictly on the full trainset. After fitting, the fitted entry is compared against the original with the same fold check; failure restores the original and the report row says "fitted behavior did not beat the original" — [calibrate.py (raw)](https://raw.githubusercontent.com/stanfordnlp/dspy/main/dspy/teleprompt/reanchor/calibrate.py)
- API: `ReAnchor(metric, *, num_threads=None, log_dir=None, require_cache=True)`; `compile(student, *, trainset, valset=None)` returns a calibrated copy; valset is scored only; `report` has `train_score_before/after`, `val_score_before/after`, and per-output `fitted` rows with `observed`, `fold_check` counts, `train_score_original/at_start/train_score`; stops at first error; generative LMs: when a field entry exists, `Predict` requests probabilities for native `bool`/`Literal` outputs and applies threshold/weights, restored if rejected — [ReAnchor API docs](https://dspy.ai/current/api/experimental/ReAnchor/)
- PR #10475 (merged 25 Sep 2026, 13 commits): fixed grids replaced by observed-probability midpoints (commit e3ec851), fold check added (b0158e0), "retain Boolean thresholds between adjacent probabilities" (827bde3); author-reported calibration-only gains: email triage 1,000 unseen-sender test emails 0.692 → 0.749; trend-report judge (8 test files) 0.813 → 0.874; trainset sizes not stated. A downstream reimplementation (OpenAgentsInc/openagents commit e7c9a1f) found "no fitted setting beat the hard-coded one on each component's own objective" — [PR #10475](https://github.com/stanfordnlp/dspy/pull/10475). Follow-ups: PR #10490 "Simplify ReAnchor calibration" — [PR #10490](https://github.com/stanfordnlp/dspy/pull/10490); an R port in `dsprrr` PR #144 — [dsprrr PR](https://github.com/JamesHWade/dsprrr/pull/144)
- **PR #10536 (open, michaelisaac-dev, 1 Oct 2026) extends ReAnchor to `dspy.Flex` programs and adds decomposition**: with a `proposer` LM, an RLM rewrites the Flex's code over several rounds into "a few narrow decisions that plain Python combines"; a rewrite is kept only if it scores higher on the validation set, or equal with fewer calls. Email triage (`weijianzhg/email-triage-action-seed`, 300 train / 200 val): 3-way (336 test) Flex(Jev)+ReAnchor 0.816 at $0.049/1k vs Predict(Jev)+ReAnchor 0.649 at $0.020 vs Predict+GEPA 0.798 at $0.272 vs RLM+GEPA 0.851 at $0.936; "needs a reply?" (1,000 test) 0.870 / 0.676 / 0.786 / 0.755. The PR's own summary: "Calibrating plain Jev alone helped only somewhat. Decomposing the decision into a few narrow questions closed most of the gap." — [PR #10536](https://github.com/stanfordnlp/dspy/pull/10536)

**B. Platt / isotonic recalibration of hosted Jev [independent-with-code]**
- **AnthusAI/Jev-Calibration** (Python; license not stated; jev-1.13.0): 8,801 unique sentiment examples, 60/40 stratified split (5,280 calibration / 3,521 test). Across 11 question setups raw ECE 0.064–0.160, Platt 0.026–0.115, isotonic 0.006–0.018. For two-option Choice `confidence = 2·p_top − 1` ("adds nothing"). Top raw band 95–100%: Noul 2,104 answers 100% accurate; Choice 5,559 answers 90.2%. Jev vs Llama-3.1-8B on 1,000 items (5-fold CV): accuracy 0.743 (Noul) / 0.776 (Choice) vs 0.722; raw ECE 0.073 / 0.147 vs 0.169; isotonic-CV ECE 0.022 / 0.016 vs 0.021; AUROC 0.828 vs 0.719. **C. Cost-sensitive thresholds and review bands [independent-with-code]**
- **gbesse/jev-utility** (Python 3.11+, MIT, "public alpha", not affiliated): `optimal_threshold`, `abstention_band`, `expected_utility`, `calibration_report`, `fit_platt`, `fit_isotonic`, `calibration_split`, `value_of_information`, `sensitivity`; CLI reads JSONL `{probability, label}`; binary cutoff **p* = C_fp / (C_fp + C_fn)** (expected cost of predicting positive C_fp(1−p) equals C_fn·p), "only optimal under the stated costs if the probabilities are calibrated"; abstention band compares expected loss of each automatic action against a declared human-review cost plus residual error at declared human accuracy (no closed form published); value of information = EU with the true state minus best EU without it (upper bound on what a better predictor can add); a threshold is labelled "optimal under stated costs, assuming calibration" and upgraded only if an attached calibration report passes a configured ECE tolerance; warns isotonic "can overfit small samples" and ECE "depends on the binning choice" — [jev-utility](https://github.com/gbesse/jev-utility); [docs/method.md](https://raw.githubusercontent.com/gbesse/jev-utility/main/docs/method.md)
- **abhixhek/jevcal** (Python 3.10+, MIT; live-verified on jev-1.13.0 on 2026-09-18): per-question thresholds for a Jev→LLM cascade. Thresholds chosen on one half of labelled data and checked on the other ("if a threshold fails on the held-out half, jevcal reports that rather than the flattering number"); confidence measures `top_prob` (default), `margin`, `entropy`, API `confidence`; `--measure auto` switches only when another measure clearly separates right from wrong; `--conservative` requires the 95% lower confidence bound to meet the target; outputs reliability diagram, accuracy-vs-coverage curve, per-answer accuracy, cost split; recommends "a few hundred real labeled examples", "under about 100 labeled rows per question, thresholds are unlikely to hold"; `label` fills missing labels with an LLM (teacher signal to spot-check); `optimize` lets an LLM rewrite questions, kept only if held-out coverage at target rises; runtime `Cascade.from_lock(path, fallback=…)` with `.source` ∈ {jev, fallback, unresolved}, fails closed without fallback. Simulator-only numbers (no Jev numbers: README says the customer agreement restricts publishing them): is_urgent threshold 0.994 handled 21.2% at 100% accepted accuracy; department 0.954 / 81.3% / 96.3%; frustration 0.875 / 98.0% / 95.4%; cascade $1.930 vs $2.25 LLM-only per 1k (14.4% saved) — [jevcal](https://github.com/abhixhek/jevcal)
- **Observed production bands**: Braintrust suggests accept ≥0.95, 0.70–0.95 to a stronger LLM judge, <0.70 human (explicitly "not default thresholds") — [Braintrust blog, 18 Sep](https://www.braintrust.dev/blog/evaluate-agent-responses-with-jev); OpenRouter refund cookbook approve if all three Nouls ≥0.9, block if any ≤0.1, else human review; repeat variance up to 0.08 (policy_covers 0.35–0.43 over four repeats) — [OpenRouter cookbook](https://openrouter.ai/docs/cookbook/building-agents/gate-tool-calls-with-jev); toolgate deny ≥0.85 / ask ≥0.55 on the max risk axis, `authorized` ≥0.8 softens one step except for secret_exposure/violates_constraint/unresolved_choice — [toolgate](https://github.com/RiskAverseTech/toolgate); EmDash routes plugin listings to an operator at ≥0.45 on any of nine Clef questions — [EmDash, 7 Oct](https://emdashcms.com/blog/how-emdash-uses-clef-to-moderate-the-plugin-registry); Edward "express gate" ≥0.98 giving 85.7% precision at 7.4% FPR — [Edward](https://github.com/VeridicalTech/Edward); Arize tunes each model's yes/no cutoff on one half of the data and scores on the other — [Arize benchmark](https://arize.com/blog/decision-model-benchmark/)

**D. Conformal / selective prediction**
- **poorjev** (MIT, Python 3.10+, local ~400 MB NLI model, each option scored as an entailment hypothesis in one batched pass): temperature fit by 5-fold CV (T = 2.71); shipped eval set 55 hand-labelled items / 160 decisions: accuracy 0.781, ECE 0.170 → 0.071, Brier 0.184; "conformal thresholding turns a target risk budget into an 'I don't know, escalate' signal" — at a 10% error budget it answers 55% and escalates the rest; on Banking77 (n=154) accuracy 0.656, ECE 0.414 (recalibration did not help: 0.416). **E. Label-free correction and drift**
- No fetched source applies CBPE/NannyML-style label-free accuracy estimation to Jev. Closest: AnyJev L0 "divides out the label prior, which is estimated without labels" (plus rotation marginalisation), raising Qwen3-8B BANKING77-20 accuracy 0.747 → 0.803 and cutting ECE 0.240 → 0.184 — [AnyJev](https://github.com/MorrisZJ/AnyJev); jev-align "squash" mode (label-free GEPA to reduce Jev's uncertainty on a fixed dataset) with the warning that "a run can pass by assigning one answer to every row" — [jev-align](https://github.com/sutro-sh/jev-align); jev-trust's "effective confidence" = observed accuracy of the matching confidence bin (needs ≥5 outcomes) else C-adjusted (C = 1 − ECE), with verdicts UNVERIFIED (<20 outcomes), FACE_VALUE (C ≥ 0.80), DISCOUNT (0.50–0.80), DOWNGRADE (<0.50) — [jev-trust](https://github.com/chunxiaoxx/nautilus-compass/tree/main/sdks/jev-trust)
- **Drift tooling**: jevcal `check` re-runs the model on the labelled data, compares to `decisions.lock.json`, exits 1 when accepted accuracy falls below target, coverage drops, or (`--strict`) the model version differs; bypasses cache — [jevcal](https://github.com/abhixhek/jevcal). stuntd computes agreement with the upstream provider over a rolling 100-decision window (min 20) and self-demotes a site to shadow below `target_agreement` 0.99 — [stuntd](https://github.com/bladedevoff/stuntd). Observed drift: 20 of Jev's multiple-choice answers changed between a 19 Sep run and the October Decision Index snapshot — [redreamality](https://redreamality.com/blog/open-decision-models-2026-survey-benchmarks/); hosted Jev run-to-run variation at temperature 0 "up to 3.5% of answers" (GLM too) — [privatemode, 24 Sep](https://www.privatemode.ai/blog/system-one-from-glm-flash). Microsoft self-reports a 1.3% average flip rate over eight perturbations for Decision-1 (0% on reversed/shuffled options) — [TestingCatalog](https://www.testingcatalog.com/microsoft-launches-decision-1-model-in-foundry/). Arcjet's "behaviour drift analysis" with Clef-flash is session-level hazard scoring with no drift statistic — [Arcjet, 14 Oct](https://arcjet.com/blog/how-we-built-ai-agent-behavior-drift-analysis-with-cloudflare-clef)
- Prompt sensitivity as a calibration hazard: Red Hat found a policy tuned for Laya raised Laya +17.83 pp (57.87 → 75.20) but lowered Jev −3.67 pp (86.20 → 82.53) — [Red Hat Developer, 2 Oct](https://developers.redhat.com/articles/2026/10/02/benchmarking-ai-decision-models-against-traditional-guardrails)

### Inferences
- The reimplementable recipe for a generic engine is now clear: (1) log raw per-option probabilities; (2) per question and per backend, fit isotonic when ≥200 labels and Platt below that (AnthusAI's curve crosses around n≈100); (3) derive the action cutoff from declared costs (gbesse's C_fp/(C_fp+C_fn)) on the *recalibrated* probability; (4) if the metric is end-to-end rather than per-question, run ReAnchor's procedure (observed-midpoint candidates, strict improvement plus 5-fold held-out sum) instead of a cost formula; (5) gate deployment with jevcal-style half-split checks and a `--conservative` lower bound.
- Base-rate shift is the dominant miscalibration mechanism on real data (Adilmp: ECE 0.157 at 19% positives vs 0.209 at 2.9%; AnthusAI's all-below-diagonal bins), which is why a two-parameter Platt map removes ~96% of error without touching ranking; this also means thresholds fit on a "hard" sample will not transfer to natural traffic, and the engine must track the live positive rate.
- Wording moves the probability scale far more than the ranking (Adilmp mean p 0.26–0.57 across phrasings at AUC 0.88–0.91). Criteria text should therefore be versioned alongside calibration maps: any edit invalidates the map.
- Conformal abstention remains unimplemented on hosted Jev; because Jev's answers are near-deterministic and rank well, split-conformal on the recalibrated top probability (or on 1 − margin) with a few hundred labels would be straightforward and is the natural "review band" formalism; poorjev's 55% coverage at 10% risk shows the coverage cost on a weak local model.

### Gaps
- ReAnchor has no published results beyond the author's two tasks and the PR #10536 email-triage table; trainset sizes for #10475 are unstated; no third party has benchmarked it against Platt/isotonic.
- No source computes Brier or reliability diagrams for Choice with >2 options or for Score on hosted Jev with human labels; AnthusAI reports accuracy only for `choice3`/`score5`.
- No label-free (CBPE-type) accuracy estimation on any decision model was found; Adilmp's base-rate-only correction is proposed, not tested.
- poorjev's conformal procedure (score function, alpha, calibration size) is undocumented; JevRL's abstention head is untrained.
- jevcal's statement that TypeSafe's customer agreement "restricts publishing Jev performance numbers" conflicts with the prior notes' reading of the MCA (no benchmarking clause); the clause was not located.
- The CDMM/"Jane Street framework" Medium article describing a three-record persistence layer (events + raw answers; recomputed decisions + gate checks; outcomes as one calibration observation per option) returned HTTP 403; its content is known only from a search snippet — [Medium](https://medium.com/@gwrx2005/jev-and-the-jane-street-framework-theory-implementation-and-a-new-quantitative-model-67a48e67a4fd).

## Key question 2: Evaluation and observability (LangSmith, Langfuse, MLflow, Braintrust, Arize, W&B, Helicone, OpenRouter, LiteLLM; decision ledgers; dashboards)

### Takeaway
Braintrust, Arize AX, Langfuse, MLflow and LangSmith all expose Jev as a judge/scorer and log per-option probabilities in span metadata, but none joins later outcomes to those probabilities or computes calibration; W&B Weave and Helicone show no Jev support. The real "decision ledger" work is in small open tools: jev-trust (append-only JSONL + outcomes + ed25519 signature), toolgate and Edward (signed audit logs with per-question probabilities), mu and jevonian (per-decision-point ledgers), wow-overseer (outcome rows for every disagreement plus a 10% sample of agreements). LiteLLM has become the de-facto multi-vendor proxy with `/v1/systemone` and `/v1/decisions`, cost headers and fallbacks.

### Cited Findings

### Inferences
- Every observability vendor stops at "probability in metadata"; none has a first-class outcome event, so calibration cannot be computed inside LangSmith/Langfuse/MLflow/Braintrust/Arize today. A generic engine should own the ledger (jev-trust's schema plus toolgate's per-question probabilities and wow-overseer's `acted`/control-arm columns) and export spans to these tools rather than depend on them.
- Signed, replayable ledgers (jev-trust, Edward, Nautilus receipts) have appeared independently three times in a month; auditability of automated decisions is treated as a product feature, suggesting the engine's ledger should be content-addressed and signable.
- LiteLLM is the cheapest path to backend-agnostic logging and fallback across Jev/Clef/Decider/OpenAI/Microsoft/Perplexity; its `refusal` entry is the only vendor-neutral representation of abstention found.

### Gaps
- No vendor documents how it bills or logs *decision* cost (Braintrust logs tokens only; Arize does not say).
- No observability platform offers reliability diagrams or ECE per question for decision models; only community CLIs (jevcal, jev-trust, AnthusAI scripts) do.
- Hev ("Jev-compatible API answered by humans", HN 13 Oct) could not be read: the page returned only a title — [usehev.com](https://usehev.com); HN listing [item 50075774](https://hn.algolia.com/api/v1/search?query=clef&tags=story&hitsPerPage=30&numericFilters=created_at_i%3E1758844800).

### Takeaway

### Inferences
- Leaderboard position is dominated by scoring policy: abstention = wrong (Decision Index) penalises exactly the behaviour a production engine wants, and JevBench's ×2+0.15 s self-hosted penalty flips speed rankings. A generic engine should treat these boards as ranking priors only and run its own coverage-at-error-budget evaluation (the metric used by AbdelStark, AnyJev, TetraJev and TypeSafe's DecisionBench).
- The failure map is consistent across suites and is the input to question design: do arithmetic and thresholds in code (Akita), add an explicit abstain/none option and check its calibration separately (When2Call 76% hallucinated tool calls; edot's "not sure" chosen 100%), keep option counts small (TREC 6→42), avoid negated phrasings on open models (Arize AUC collapse to 0.17–0.54), and expect rare-class collapse (DAIR emotion zero-probability on 16%).
- Private new-domain splits are the only thing separating "trained on public benchmarks" from generalisation; Clef's 20-point drop vs Jev's 3 is the clearest evidence that open-model card numbers overstate real-world transfer.

## Key question 4: Reliability constructions (lead-by-k, voting across decision models, red-flagging, guarded rollout and auto-revert, shadow tooling, blind audit sampling, HITL queues)

### Takeaway
The month produced working code for every construction except formal lead-by-k on hosted Jev: majority/unanimous/mean voting across heterogeneous decision models (flock, merged 11 Oct), compare-mode with control-arm outcome rows (wow-overseer), agreement-routing across four readings with published coverage–accuracy curves (TetraJev), early-stopped rotation voting (AnyJev's rotation budget: 7.2 of 18 rotations at a 1% target), both-polarity asking (jev-trust), shadow→live promotion with automatic demotion on agreement loss (stuntd), per-decision-point shadow/active switches with a ledger (mu), CI gates that fail on drift (jevcal), and labelling loops that mix uncertainty sampling with random audit (jev-align). Measured evidence that these improve accuracy is thin: TetraJev's fusion matches Jev on some suites at reduced coverage; cascades still inherit correlated errors.

### Cited Findings

### Inferences
- A generic engine can implement lead-by-k today as AnyJev does for rotations: issue the first k reframings/rotations/backends, stop when the leading option's margin over the runner-up reaches k votes, otherwise continue to the budget and route ties to review — the measured 60% call saving at a 1% disagreement target is the relevant cost model. Because hosted Jev is near-deterministic per request, the diversity must come from reframing, option rotation, polarity flip, or a second backend (Clef/Decider/OpenAI), exactly the axes flock and wow-overseer expose.
- Cross-backend voting is cheap (Clef-flash $0.038/M, Jev $0.042/M, OpenAI $0.10/M) but the independent evidence says Clef and Jev err in different places only sometimes (nikcub 78.6 vs 79.8 with different misses; Akita: Microsoft and Jev "tie on aggregate but miss different cases"), so disagreement rate should be measured per question before trusting a majority rule; "a refusal is no vote" (flock) and "unanswered = wrong" (Decision Index) are opposite policies the engine must choose between explicitly.
- Shadow mode has matured from "log only" (jev-judge) to a state machine with promotion/demotion criteria (stuntd: 24 h shadow, 0.99 rolling agreement, 2% continuous audit, novelty gate). That is the closest existing thing to guarded rollout with auto-revert for a learned decision policy and is directly reusable for threshold-set rollouts: treat each new calibration map/threshold set as a "head" in shadow, promote on agreement, demote on drift.
- The repeated lesson from Arcjet (feedback loop), toolgate (confirmation memory never lifts a deny) and the OpenRouter cookbook (reviewers cannot alter arguments) is that the ledger must separate *model-visible state* from *engine outputs*, or the engine will learn from its own decisions.

### Gaps
- No measured comparison of a heterogeneous decision-model majority (Jev+Clef+Decider) vs single model on the same labelled set; flock and wow-overseer ship the mechanism but no numbers.
- No shadow→enforce outcome deltas published (false-positive rate before/after promotion); stuntd and mu publish mechanisms and offline agreement only.
- TetraJev's strict vs unanimous boundary is undefined on the page.
- MAKER-style lead-by-k on hosted Jev with reframed questions: still no implementation or measurement found (prior notes' gap stands).

### Inferences
- For a generic engine the backend abstraction is now trivial: SystemOne over HTTP covers Jev, Clef (hosted, Ollama, llama.cpp, SGLang, vLLM), Strands, Laya, H2O, d3, AnyJev and LiteLLM; only OpenAI (own schema, translatable), pplx-decider (Python class) and Liquid d1-3B (Python `system_one()`) need adapters. Per-backend differences that matter for policy: option-count caps (26 vs 255), context caps (8k pplx, 24k hosted Clef-flash, 32k Jev state), tie-breaking by order (Ollama), and whether `confidence` exists (Strands/Clef yes; Noul never).
- "Open beats hosted" is now true at 27B on independent suites (Akita, Decision Index) but costs ~49 GB of weights and 1.4–1.5 s per decision on a consumer APU, so the local tier splits into: 27B for batch/offline labelling and audit replay; 4B (Jebadiah, Mapika, Kev 4B, H2O) for ~200 ms online decisions at 87–90%; encoders (Laya, Julia, Decima) only after task-specific fine-tuning.
- Quantisation is safe for the backbone (Q5 ≈ 99.8% agreement) but the decision head must stay BF16/F32 and cannot be imatrix-calibrated; any engine that swaps quantisations should replay its calibration set (jevcal `check --strict` semantics) because calibration maps are not transferable across precisions.

## Key question 6: Distillation and fine-tuning (Jev-labelled data vs MCA, LoRA on Strands/Clef, Cloudflare RL platform, synthetic criteria generation)

### Takeaway
Distillation from Jev is happening openly despite MCA §2.3(b): AutoTrust trained JEV-9B on 498,010 Jev-labelled rows collected via OpenRouter and reports KL 0.019 to the teacher, and stuntd records any provider's answers as labels to train per-question heads (teacher can be Jev, Clef, Kev, Perplexity). Domain fine-tuning of Strands Decider is cheap and effective (DTR recipe: 0.493 → 0.979 strict accuracy, 0.545 → 0.864 on held-out chapters, 201 steps on an A10G) and the authors say fine-tuning "on your questions" also improves calibration. Synthetic criteria generation has four working implementations (jev-align/GEPA, jevcal `optimize`, DSPy Flex decomposition, parallel.ai's five-round rewrite), all gated by a held-out check, with lifts from +0.3 to +13.4 AP depending on how weak the base model is.

### Inferences
- The legally clean distillation path is: label with an Apache-2.0 decision model (Clef, pplx-decider, d3, Strands) or an LLM, not Jev; stuntd's proxy design already supports swapping the teacher. If Jev is used in production, the engine's ledger of Jev outputs is itself "Output" under the MCA and should not feed a head that imitates Jev; outcome labels (human truth) are not Output and can train anything.
- Soft 0.5 targets for ambiguous rows (DTR recipe) and the `refusal`/`none` option are the two mechanisms by which fine-tuned decision models learn to abstain; an engine that wants calibrated abstention should emit duplicated half-weight rows for reviewer disagreements when building fine-tuning sets.
- Criteria rewriting is a larger lever for weak models than for Jev (+13.4 vs +1.0 AP), and can hurt a strong model (Red Hat −3.67). Rewrites must therefore be versioned per backend and accepted only on a held-out split, which every tool above already enforces; the engine should treat criteria as parameters with the same guarded-rollout path as thresholds.

### Gaps
- No published LoRA fine-tune of Clef/Clef-flash by a third party; Cloudflare's platform has no public dataset/reward spec.
- No source quantifies calibration (ECE) before vs after domain fine-tuning on Strands (DTR PR defines ECE but reports none).
- AutoTrust's compliance with TypeSafe's terms, and TypeSafe's response, are undocumented; no takedown or statement found.
- No measurement of whether a Jev-distilled student inherits Jev's base-rate miscalibration (distillation ECE is measured against the teacher only).

### Inferences
- The engine's cheapest win is structural: one request per state with every question (including speculative ones) attached, since the ~261-token envelope is paid per request and output is free; coalescing concurrent requests on the same state digest into one call is the obvious next step nobody has shipped.

- Budget enforcement belongs in the proxy layer (LiteLLM) or the engine, not the model vendor; TypeSafe's 402 outage (wow-overseer, 10 Oct) shows that credit exhaustion is also an availability event, so fail-mode policy must cover HTTP 402.

### Gaps
- No tool implements request coalescing or near-duplicate state detection; only exact-key caches exist.
- jevcache's licence, language, TTL and savings arithmetic are unclear; no independent measurement.
- No published cost model for Workers AI "neurons" for Clef beyond Akita's note of a 10k/day allowance.

## Implementation review: evidence before enforcement (2026-10-20)

The current engine's point-estimate rollout and exploratory threshold fitting are useful
controls, but neither certifies the final selected policy's accuracy.

- **Independent validation.** [Learn then Test, section 3.2](https://arxiv.org/html/2110.01052)
  treats selective accuracy as a risk-control problem and uses binomial testing with
  correction when choosing among candidate policies. For ratchet, begin with one frozen
  candidate, an independent validation set, and a predetermined evaluation point; avoid
  introducing a general multiple-testing framework before that path works.
- **Repeated inspection.** [Howard et al., confidence sequences](https://arxiv.org/abs/1810.08240)
  distinguish time-uniform inference from fixed-time intervals. Repeated `evaluate()` calls
  on overlapping windows do not inherit the confidence level of a one-time interval.
  Conservative demotion can remain an explicitly empirical safeguard.
- **Which population was labelled?** [Lakkaraju et al., selective labels](https://www.cs.cornell.edu/home/kleinber/kdd17-selective.pdf)
  explain why outcomes observed under a selection policy cannot simply evaluate arbitrary
  alternatives. In this engine, random audits sample existing acts only. They cannot
  establish performance below the action threshold. Shadow labels also need a representative
  sampling protocol; the mode field alone is insufficient.

Calculated illustration: for independent Bernoulli correctness on one fixed policy, an
all-success sample of size `n` has exact one-sided 95% lower bound `0.05 ** (1 / n)`.
At `n = 20` that is 0.8609. Reaching 0.98 requires
`ceil(log(0.05) / log(0.98)) = 149` all-correct acted examples. A policy with true accuracy
0.95 produces 20/20 with probability `0.95 ** 20 = 0.3585`. These calculations do not cover
correlated retries, threshold selection on the same labels, or repeated evaluation.
